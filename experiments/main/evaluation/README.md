# 统一评测与分析

`evaluate.py`评测最终EMA，`analyze.py`生成单训/混训各任务四条件表及图。外层入口为 `run_main.sh --stage evaluate/analyze`，不生成或训练缺失模型。

## 一致协议

所有任务：当前前景/背景＋32步动作图，逐步推演32次，不提前停在固定点。两个干预分别得到终态，按公共定义计算同一 `change_f1` 与 `cell_acc_mask`。不报告任务专属metric，不让水沙绕过相同mask规则。

`change_f1`针对任一层发生变化的格子；`cell_acc_mask`的mask由初态和真实终态定义，预测不能修改关注区。空变化且预测空变化时F1为1，这是统一公共约定。

## 身份验证

每任务评测目录含 `metrics.json`、`samples.npz`和 `complete.json`。样本保留两种metric、两层预测、场景ID与group。标记绑定最终checkpoint、训练标记、结果文件哈希。加载时重新根据预测状态计算metric，核验与冻结bench对应。

已提交评测变化则拒绝；未提交结果可重推演；缺最终模型不会触发训练。所有记录模型全量预检在任意推理前完成。

## 统计

先按场景平均两个干预，再平均训练种子，最后对场景配对bootstrap，默认10000次、seed12345；相同场景在四条件中保持配对。每任务输出process−state/partial/shuffle差值与95%场景区间，另报种子标准差。只有一个种子时标准差缺失，不填0。

总平均按任务等权，不因T01有512场景而更重。不将多个任务混作同一场景总体，不把场景区间当跨种子区间。默认所有格完整才分析。

输出 `analysis/main_boot10000_seed12345[-编号]/results.json`、`results.md`，以及 `figs/single.png/pdf`和 `mixed.png/pdf`。重复分析创建新编号目录，不覆盖已有分析。

T01原四划分仍保留在逐场景group，可用于后续扩展分析；当前核心表按任务汇总。T01测试若参与设置选择，应称锚点/开发结果，不能称全新未使用测试；新任务使用独立空间迁移测试。
