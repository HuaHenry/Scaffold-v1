# 实验 07_02：按数据规模训练五个完整 epoch

实验计划：`plan/07_02_等轮次数据预算曲线.md`。本实验与原 `README.md` 所述的**每档固定 12000 步**的实验 07 相互独立；原运行方法 `run_all.sh` 不变，结果也不能合并为一条曲线。

## 训练预算

每档使用同一训练集前 N 个 episode；`state` 和 `process` 每个 episode 均为 64 帧。取跳过片段重置帧后的有效相邻帧转移，各训练 **5 个完整 epoch**：每轮随机打乱、无放回，每条转移恰好训练一次，保留不足 batch 256 的最后一批。每档训练总步数由实际可训练转移数决定：

| 档位 N | `state` 每轮转移 | `process` 每轮转移 | 五轮 `state` 更新 | 五轮 `process` 更新 |
|---:|---:|---:|---:|---:|
| 16 | 896 | 944 | 20 | 20 |
| 4096 | 229376 | 241664 | 4480 | 4720 |

其余 15 个档位包括 24、32、48、64、96、128、192、256、384、512、768、1024、1536、2048、3072，分别按 `5×ceil(56N/256)`、`5×ceil(59N/256)` 计算更新数。`process` 每 episode 的有效转移为形成 31、操作 28；为了做到“每条恰好训练五遍”，不再强制 50:50 批内采样，形成比例为 31/59。两条件比较的是**相同原始视频帧预算、相同完整轮次**，不是相同的更新步数或有效转移数。

学习率按各自总步数余弦衰减，预热不超过 300 步且不超过总步数的约 5%。每一轮结束后仅按独立验证集一步 `cascade_acc` 选择最佳 EMA（并列取更早轮次）；FormBench 仅作最后评测，不能用其分数选模型。16 档只有约 20 次更新，小档表现低不能通过暗中增加步数纠正；应如实报告。

## 用户自行运行

在实验目录执行：

```bash
cd /data/huazhouqi/Scaffold-v1/Scaffold-v1/preresearch/07_budget_curve
GPUS=0,1,2,3 bash run_02.sh --tag five_epochs
```

默认仅训练种子 0。`run_02.sh` 会复核现有 `game_code/output/data_v3_curve_4096`、其中独立的 `validation` 和统一去重的 `bench.npz`，审计 17 个档位后生成 34 个新任务，再评测并分析；不会覆盖原实验 `experiments/preresearch/07_budget_curve/` 中的结果。新结果在 `experiments/preresearch/07_02_budget_epochs/<运行名>/`，任务清单为 `jobs/curve_epochs5_seeds0.json`，曲线在 `analysis/budget_curve_epochs5_seeds0/`。

断点续跑需沿用第一次输出的运行名：

```bash
FW_RUN=<07_02运行名> GPUS=0,1,2,3 bash run_02.sh
```

可以用 `EPOCHS`、`SEEDS` 调整完整轮数或训练种子，但参数变化应新建运行，不能在同一运行中混用；同一曲线的所有档位须共享相同的 epoch 数、验证集和 bench。单种子的配对题目区间只反映题目差异，不代表重新训练后的稳定性。**脚本由用户自行启动；编写代码不会自动启动实验。**
