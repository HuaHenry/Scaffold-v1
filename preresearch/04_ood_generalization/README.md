## 3. 可选：完整尺度与组件探针

```bash
env -u FW_RUN bash run_all.sh --tag ood_with_probes \
  --with-probes --gpus 0,1,2,3 --per-setting 32
```

可只做一个探针：`--with-probes --probe scale` 或 `--with-probes --probe components`。也可 `--gpus cpu` 在CPU上评测，但模型预测会更慢。

### 单结构尺度扫描

- 塔的蓝图高度4–16，桥的总跨度4–14；桥的内部空跨为总跨度减2。
- 默认每个设置最多接受32个唯一、稳定场景；每尺度最多尝试512次，可用 `--max-attempts` 调整。
- 保持原网格、物理规则、模型不变，只有评测结构大小变化。塔4–7、桥4–8为训练生成器的参数范围，**不是完整场景分布内标签**。
- 使用可稳定的单次拆除干预对，并记录各尺度接受率、因不稳定／重复／没有有效干预对而被拒绝的数量。
- 桥跨度超过10时遵循现有规则强制砖梁。因此曲线同时受材料限制影响，不能称为严格等材料的纯尺度实验。
- 训练参数范围内先检查引擎参考预测整图准确率是否至少95%；不达标则停止该无效探针，不继续评测模型。没有有效样本不能算通过。

### 相同组件：单独与组合

- 从原 `combo_ood` 场景提取组件，保持位置、材料、几何形状一致，再分别评测单独出现和组合出现。
- 干预必须只作用于一个组件；跨组件脚本会跳过并记录。单组件收到原来针对自己的干预，其他干预替换为无动作。
- 比较时只取每个干预的目标组件，并以整个组合家族为抽样单位，不用无关组件的无动作分数制造“单组件已经掌握”的假象。
- 同时报告两侧都有非空连锁的子集，避免“没有变化也得F1=1”掩盖问题。
- 并排放置不一定产生机械交互；单组件自身预测差时，不能将组合错误全部归因于组合能力。替换无动作后的单组件排序不与原组合排序比较。

新生成的单组件和尺度场景不得与原训练、验证或评测的完整终态重合；组合探针的组合侧明确复用原测试场景以保持配对，不当作新独立样本。生成空间不足时允许部分或零覆盖，**不重复填满、不补零分、不删除旧数据绕过隔离**。

## 4. 统计怎么读

- 默认bootstrap为2000次；`--boot`调整次数，`--seed`是统计重采样种子，不是训练种子。
- 条件差值保持同一场景配对；不同测试划分独立重采样；组件对照保持同一家族配对。
- 难度组先平均同一场景中满足条件的干预，再平均场景，不把两个干预当两份独立样本。
- 分组不足8场景只作描述，只有1个场景不算区间，空组显示缺失，不当成零。
- 成绩差距：`参考成绩−其他成绩`，正值表示下降；收益变化：`(process−对照)(其他)−(process−对照)(参考)`，正值表示相对收益更大。
- 所有区间只反映场景抽样波动，不包含重复训练的波动；不自动报告多重比较显著性或给所有分箱盖“通过”标签。
- 已有场景的尺度趋势混合了组件数量、类型和材料，只是观察性曲线；可选单结构扫描更受控，但仍需报告接受率与材料边界。
