# 08 扩展：含失误的形成过程（process-noisy）

优先级 P1 ｜ 对应假设 H1、H2 ｜ 公共约定见 `00`。

## 1. 范围与目标

**只使用原03的单个结构干预任务，不使用 main 扩展任务集；所有条件只训练 seed0。**

比较正确形成过程与“犯错后纠正”的形成过程，检验失误带来的真实物理变化是否改善连锁 F1。原03冻结来源为 `20261111-044057_four_conditions`，训练源包含81,920集。验证集、bench、场景顺序、世界种子和操作片段不变。

源码：`preresearch/08_noisy_formation/`。数据、模型、日志和分析只写入 `experiments/preresearch/08_noisy_formation/`；不修改03、06或 main。

## 2. 条件与训练预算

| 条件 | 名义失误概率 | 训练器条件 |
| --- | --- | --- |
| `state` | 不加噪 | `state` |
| `process` | 0 | `process` |
| `partial` | 不加噪 | `partial` |
| `shuffle` | 不加噪 | `shuffle` |
| `process_noisy_low` | 0.1 | `process` |
| `process_noisy_high` | 0.3 | `process` |

六个条件模型，不是六个任务，也不是多种子。默认每条件81,920集、94,400次更新、batch256；`video`合法转移均匀有放回采样，形成监督比例不额外改变；验证只监控，提交最终更新的EMA，不选择验证best。默认模型与06一致：dim384、depth8、heads6、lr3e-4、lr_min3e-5、warmup300、wd0.05、EMA0.999、change_weight8、unroll1、val_every500。

数据可以先派生M集，再在 `prepare --episodes N` 选择相同 `[0,N)` 前缀，要求N≤M≤81,920。验证和bench不截断。小N不代表训练器解压峰值内存同样缩小；沿用原训练器的全帧加载方式。

## 3. 失误与严格配对

只替换 `process` 前32帧形成；后32帧前景/背景、操作动作、`cont`、`phase`逐位保持原数据。四个无噪基线直接读取冻结来源，不重新采场景。

### 3.1 固定真实时间轴

- frame0：原世界地形，不执行动作。
- frame1–20：读取原动作并执行扰动/后补。
- frame21–27：状态感知修复，同时补完原本较晚的建造内容。
- frame28–31：四个无动作稳定tick。

**每相邻帧只执行一次真实 `tick()`。不得延长物理时间后抽帧，不使用 `step()` 压缩多tick，不直接赋值恢复运行世界网格。** 支撑预检只在隔离副本应用合法动作，不推进tick。

### 3.2 三种等概率失误

在frame1–18中实际检查到的原 `place` 动作上，以p尝试一种失误：

1. **延迟/乱序**：延期1–6个真实tick后补做，后补时间封顶frame20。
2. **邻格错放**：尝试相邻空格，再后补原动作；修复阶段从方块实际位置移除错误部分并补齐正确结构。不能假设落块仍在最初错放位置。
3. **遗漏后补**：计划延期10–20个tick，封顶frame20；这是长延迟后补，不是永久缺失。

同帧同 `(x,y)` 只能一个监督token，前后景也不能覆盖。冲突推迟；不合法动作不进入保存动作/监督，统计跳过数。修复按实际前后景先清除错误部分，再只补放已获得支撑的前景和可附着背景；同格跨层修复分到后续真实tick。

`dune` / `pond` 整集不加噪。p=0逐位保留原形成。未触发失误的集也保留原形成，避免无失误时改变建造调度。加噪失败则保留同场景原轨迹，不丢弃或重采样。

最终前景/背景必须等于原frame31、已稳定且无规则违例。所有物理变化由原世界规则自然产生。

### 3.3 审计与门禁

`manifest.json` 与每档 `episode_audit.json` 记录：

- 名义p、三类尝试数、成功错放数、检查到的候选动作数、实际轨迹变化集数。
- 非流体集分母上的回退率、有效变化率；流体排除数、回退原因、非法动作跳过数。
- 形成31个转移中“动作执行后、tick前”到“tick后”的物理变化占比。
- `remove`占比、坠落材质格变化代理、每建造tick动作数量分布。坠落代理不是独立坍塌次数。
- 地形/成品一致、后32帧与动作一致、源轨迹严格重放、总31tick；`cont/phase`直接复制。

训练门禁：两档非流体回退率均<10%（可进一步调严格）；物理变化 `process < low < high`，high≥30%。失败数据保留诊断文件，退出失败；重复运行、prepare和训练不能将其当作合格数据复用。源码、源输入、数据文件、协议和模型完成身份变更均拒绝沿用旧版本。

修复会增加单tick动作数量；必须报告分布，不将它描述为与专家相同的动作密度。这一实验同时改变失误内容与纠正动作，不能把增益全部归因于坍塌。

## 4. 直接运行命令

以下命令从项目根运行；本机有实验依赖的Python为 `/usr/bin/python3`。

### 4.1 先生成数据（不启动训练）

```bash
cd /data/huazhouqi/Scaffold-v1/Scaffold-v1
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/generate_data.sh --out /data/huazhouqi/Scaffold-v1/Scaffold-v1/experiments/preresearch/08_noisy_formation/data_v1 --episodes 81920 --workers 8
```

该命令同时派生low/high。显示分条件进度、集/秒、阶段ETA；源哈希、解压、压缩和最终审计显示心跳。样本100%不等于整次完成，最终核验后才报complete。`--dry-run`只预检原03，仍会读取全套源文件哈希。并行度不改变样本或身份。

全量临时源前缀约15.3GiB，另需一档派生前后景约15.3GiB；同时保留两档压缩产物与动作JSON，建议至少预留60GiB空间。准确压缩后大小依实际数据而定。

### 4.2 绑定并训练六个单种子条件

```bash
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/run_all.sh prepare --run noisy_v1 --data /data/huazhouqi/Scaffold-v1/Scaffold-v1/experiments/preresearch/08_noisy_formation/data_v1 --episodes 81920
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/run_all.sh run --run noisy_v1 --gpus 0,1,2,3
```

`prepare`不训练；`run`每卡一个任务、训练后评测，所有模型只有seed0。按实际空闲GPU修改 `--gpus`，不要与06占用相同卡。默认不主动启动训练。重复运行只复用身份检查通过的已完成训练；中断训练从step0重训，不恢复optimizer。源数据派生中断则保留目录，用新数据版本，不覆盖半成品。

### 4.3 省去四个基线训练（可选）

若06同规模seed0四条件均完成且预算、数据、超参、最终EMA匹配，改用：

```bash
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/run_all.sh prepare --run noisy_reuse_v1 --data /data/huazhouqi/Scaffold-v1/Scaffold-v1/experiments/preresearch/08_noisy_formation/data_v1 --episodes 81920 --reuse-scale-run 20261113-082637_data_scale_final
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/run_all.sh run --run noisy_reuse_v1 --gpus 0,1,2,3
```

这样只新训low/high；四个基线只读引用，不复制或改写06模型，评测仍写08。四条件必须全部完成，缺一就prepare失败，不能悄悄转成重训。当前是否全部完成应以prepare检查为准。

### 4.4 纯评测与分析

```bash
PY=/usr/bin/python3 bash preresearch/08_noisy_formation/run_all.sh evaluate --run noisy_v1 --gpus 0,1,2,3
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 -m preresearch.08_noisy_formation.exp.analysis --run noisy_v1
```

纯评测先核验全部六个最终模型，缺失时直接失败，不触发训练。使用原03完整512场景bench，输出独立 `evaluate/<variant>_seed0/`。

分析输出 `analysis/results.json`、`table.csv`、`dose_response.svg`：low/high分别对四基线、high对low、0/0.1/0.3剂量趋势、全部与各split、`n_changed>=3`干预子集。后者仅为依赖违例代理，不是精确“拆承重块”标签。两个干预按场景聚合，再做配对bootstrap；区间只表示场景不确定性，不代表训练种子不确定性，不自动宣称显著。

## 6. 验收与解释

1. 全量数据通过第3.3节门禁与严格配对。
2. 六个条件均有匹配的seed0最终EMA及完整bench评测；允许四基线只读复用。
3. 产出连锁F1剂量图、配对差值与场景区间、依赖违例代理子集。
4. 无论是否提升都如实报告，不预设百分比增益；单种子结论不扩大为多种子稳定性结论。
