# 08 扩展：含失误的形成过程（process-noisy）

优先级 P1 ｜ 对应假设：H1、H2（针对形成数据缺少负例）｜ 公共约定见 `00`（数据变体接口 §2）

## 1. 目标

当前 process 的形成片段由专家按正确顺序搭建，几乎从不犯错（形成片段中物理引起变化的转移仅占 9.6%）。但"顺序为什么重要"恰恰体现在**错误顺序会塌**。本实验构造"会犯错并纠正"的建造者，检验含失误与坍塌的形成过程是否比专家式更有帮助。

## 2. 意义

- 最贴近"agent 在 Minecraft 里自己搭建"的版本：真实 agent 的建造必然有试错。若含失误的形成最有效，直接为第 II / III 篇（agent 集群搭建产生训练视频）提供动机。
- 若专家式无增益而含失误有增益，形成缺口的表述应修正为"含依赖违例与失败的形成过程才携带结构信息"，是更精确的结论。
- 若都无增益，则强化负结果的可信度（我们给了形成过程最大的机会）。

## 3. 实验设计

新增两个条件（与 process 同构：32 帧形成 + 4 个操作片段，T=64，同场景、同世界种子、同操作片段）：

| 条件 | 失误概率（按动作） |
| --- | --- |
| `process_noisy_low` | p = 0.1 |
| `process_noisy_high` | p = 0.3 |

### 3.1 失误类型（`datasets.noisy_actions(actions, rng, p) -> list[Action]`）

对专家动作序列逐个处理，以概率 `p` 触发其一（等概率）：

1. **乱序**：把当前动作推迟到之后第 `d ∈ [1,6]` 个动作之后（例如在两端支撑之前放中段横梁，导致它坠落）。
2. **错位放置并纠正**：先把方块放在相邻的空格 `(x±1,y)` 或 `(x,y±1)`，再 `remove`，然后在正确位置放置。
3. **遗漏后补做**：跳过该动作，在之后 10–20 个动作处（或序列末尾）补做。

约束：
- 不得改变**最终结构**：用逐动作 `step()` 的参考构造验证加噪序列的最终前景 / 背景与专家序列逐格相同（dune / pond 等流体场景不加噪）；不满足则丢弃加噪、改用 p=0 序列，丢弃率要求 < 10%。
- 加噪后序列变长（错位放置多 2 个动作），`chunk_size = ceil(len/27)` 自动增大。
- 失误的物理后果（方块坠落、连锁）由 `tick_frame` 自然产生，**不得人工伪造**。

### 3.2 审计统计

每个条件报告：形成片段中"物理引起变化"转移占比（专家式 9.6%，期望 low ~15–25%，high ~30–45%）、`remove` 动作占比、坠落事件数、`chunk_size` 分布。

### 3.3 评测

同实验 03 的 bench、协议 `video`、冻结超参、3 个种子。比较对：`noisy_*` vs `process`、vs `state`、vs `partial`、vs `shuffle`；噪声水平（0 / 0.1 / 0.3）的剂量-反应。额外报告 bench 中"依赖违例类"子集（拆承重块且其上有被支撑结构，用 `n_changed >= 3` 近似）。

## 4. 实现（本实验独有部分）

```bash
python run.py --gen-train --data-dir output/data_noisy_low  --builder noisy --p 0.1 --conditions process
python run.py --gen-train --data-dir output/data_noisy_high --builder noisy --p 0.3 --conditions process
python -m exp.make_jobs noisy
python -m exp.run_queue --jobs exp/jobs/noisy.json --gpus 0,1,2,3 --eval-after
python -m exp.analysis.noisy_table --out results/noisy.json --table results/tables/noisy.md
```

pytest：（1）每种失误的单元测试：最终结构不变、动作合法（错位放置的格放置时为空）；（2）固定种子逐位可复现；（3）第 0 帧为空地形，第 31 帧与专家式成品逐格相同；（4）`p=0` 时与专家式 `process` 逐位相同；（5）`audit.json` 增加 `noisy` 节。产出图表：Fig.7 的一格。

## 5. 验收标准

1. 噪声水平 0 / 0.1 / 0.3 的"物理引起变化"占比单调递增，且 high >= 30%。
2. 加噪丢弃率 < 10%；各水平场景分布、帧预算、操作片段与 `process` 一致。
3. 6 个训练任务完成并评测，产出噪声水平 -> 连锁 F1 的剂量-反应图。

## 6. 预期结果（先验判断）

- 含失误的形成片段包含"放错就塌"的负例，直接教授依赖关系：预期 `noisy` 的连锁 F1 高于专家式 `process`，尤其在 `scale_ood`（更长承重链）；先验：low 高于 process 约 55%，high 高于 process 约 50%；更高噪声可能因帧间跳变变大开始伤害（倒 U 型）。
- 若 `noisy_*` 也不优于 `partial`：说明"见到多样的、有物理后果的状态"比"形成的因果顺序"更关键，支持情景 B。
- 即使有增益，幅度预计只有几个百分点；强调剂量-反应趋势，不夸大。

## 7. 风险与备选

- 生成器复杂：来不及全做时只实现"乱序"一种（最贴近依赖关系，能产生"中段横梁先放而坠落"的代表性负例）。
- 失误后纠正使最终结构不变，但中间态可能与专家式不同；只要求最终结构一致。
