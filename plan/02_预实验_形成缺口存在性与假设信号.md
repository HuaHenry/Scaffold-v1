# 02 预实验：形成缺口存在性与假设信号

优先级 P0（主实验的前置）｜ 对应假设：H1、H2 的前提 ｜ 前置：实验 01 的 V1、V2 通过 ｜ 公共约定见 `00`（协议 §5、指标 §6、模型 §8、训练 §9、统计 §12）

## 1. 目标

在投入主实验与消融之前，用最小代价回答三个**前提性**问题，并事先写好"每种结果之后做什么"：

- **Q1 覆盖机制（不训练）**：process 数据相对 state，是否真的让 bench 里"会发生的局部物理变化"被见到得更多？没有覆盖增量，就没有理由期待 removal 级联上的增益。
- **Q2 缺口存在性（形成侧探针）**：只见过成品的模型，在**形成转移**（放置、建造中的沙/水掉落等）上是否真的差？process 模型是否能学会？shuffle 对照是否真的破坏了形成转移？这检验"形成缺口"这个前提本身，以及 H2 所依赖的 shuffle 对照是否有效。
- **Q3 信号读数（4 条件 × 1 种子）**：在 FormBench 上 process 与 state 的差，相对实验 01 的 MDE 是什么量级？

## 2. 意义

FormBench 目前只测"拆掉一块后的连锁"（操作侧），而假设谈的是"形成"。游戏引擎是马尔可夫的：成品加物理已经决定了任何拆除的后果，所以形成数据对拆除连锁的帮助只能来自**状态覆盖**与**放置转移的补充监督**，而不是额外信息。因此存在三种可能：增益出现在操作侧、增益只出现在形成侧、两侧都没有。本实验在不偷看假设的前提下，先判断我们处于哪一种，并据此决定主实验后的叙事与优先级，避免 11-08 才发现评测量错了东西。

## 3. 实验设计

### 3.1 局部规则覆盖度（Q1，CPU，约 10 分钟）

对每个训练条件 `c`（`video` 协议下的全部转移），为每个**发生变化的格** `u`（目标与上一状态在任一层不同）构造键：

```
key(u) = ( prev_fg[3x3 around u], prev_bg[3x3 around u], act_map[3x3 around u], next_fg[u], next_bg[u] )
```

越界取 255。再为 bench 的真值轨迹构造同类键：第一步是 `(ctx, action) -> fut[:,k,0]`，之后是 `fut[:,k,j-1] -> fut[:,k,j]`（动作图全 0）。覆盖度 = bench 的键在条件 `c` 的键集合中出现的比例，同时给 **5×5 严格版**。分别报告：

- 按划分（4 个）、按步（第一步 / 其后连锁步）；
- 只统计"连锁键"（排除被拆的那一格）；
- `process − state`、`partial − state`、`shuffle − state` 的差，以及仅形成片段所贡献的新增键占比。

### 3.2 形成侧探针（Q2）

训练 4 个条件各 1 个种子（`{state,process,partial,shuffle}_s0`，位置 `runs/main/`，将被实验 03 复用）。在验证集（seed 1000，32 个 episode）上做**教师强制的单步**评测：输入真实上一帧与动作，预测下一帧。分三类转移：

| 类别 | 来源 | 定义 |
| --- | --- | --- |
| 形成·放置 | process 验证集 `phase==0, cont` | 变化格全部落在动作格内 |
| 形成·物理 | 同上 | 动作格之外还有变化（约占 9.6%，00 §14） |
| 操作 | state 验证集 `phase==1` | 对照类：所有条件都见过 |

指标：变化格准确率（该格 fg 与 bg 都对）、`trans_exact`（整帧完全正确）。条件之间做样本层面的配对 bootstrap。

### 3.3 信号读数（Q3）

用 3.2 的 4 个模型在 FormBench 上评测（00 §10），报告 `process − state`、`process − partial`、`process − shuffle` 在 4 个划分 `cascade_f1` 上的差（单种子，只含样本噪声，CI 偏窄，仅作方向判断），并与实验 01 的 `MDE` 比较。**这一步只用于决定叙事与优先级，不得据此调超参、改数据或改 bench。**

## 4. 实现（本实验独有部分）

需要先补一项公共扩展（写入 00 §2）：`run.py --gen-val` 必须为**四个条件**各生成验证集（`output/data_val/val_{condition}.npz` 及动作文件，布局与训练一致，seed 1000，剔除与训练成品重复的场景）。

```bash
python -m exp.analysis.coverage --data output/data --bench output/data/bench.npz --out results/pilot_coverage.json
python -m exp.make_jobs pilot_signal        # 4 个任务：{state,process,partial,shuffle}_s0
python -m exp.run_queue --jobs exp/jobs/pilot_signal.json --gpus 0,1,2,3 --eval-after
python -m exp.analysis.formation_probe --runs runs/main --val output/data_val --out results/pilot_probe.json
python -m exp.analysis.pilot_decision --out results/pilot_decision.md
```

- `exp/analysis/coverage.py`：用 numpy 向量化窗口提取，键用 `bytes` 或 64 位哈希（用 `hashlib.blake2b(digest_size=8)` 以保证跨进程确定）；3×3 与 5×5 两个版本；输出每个条件、划分、步类型的覆盖度与键集合大小。
- `exp/analysis/formation_probe.py`：直接调用 `model.step`（不经过 rollout）；分类规则如上；输出 `by_class × by_condition` 的指标与 `process−state`、`process−shuffle` 等差值及 95% CI。
- `exp/analysis/pilot_decision.py`：读取 `results/pilot_*.json`、实验 01 的 `recommendation`，按 §5 的**预先登记表**自动给出结论并写成 `results/pilot_decision.md`；阈值来自 `exp/configs/pilot_decision.json`，**必须在查看任何 bench 读数之前提交**。
- pytest：构造一个小例子验证窗口键（越界、同键去重）；`formation_probe` 的分类互斥且并集等于所有形成转移。

产出：附录表 A2（覆盖度）、图 A1（形成侧探针柱状图，按转移类别 × 条件）。

## 5. 验收与决策（预先登记，结果出来后不得修改阈值）

先给三个信号：

- **G1（形成缺口存在）**：形成·放置 或 形成·物理 上，`process − state` 的变化格准确率差 ≥ 0.15 且 CI 排除 0；同时**操作**类上 `|process − state|` ≤ 0.03（缺口是形成特有的，不是整体变差）。
- **G2（shuffle 对照有效）**：形成类上 `process − shuffle` ≥ 0.05 且 CI 排除 0。不满足时 H2 无法检验，须先检查 shuffle 数据的帧序与动作是否错位（`extra[e]["order"]`），修复后重训。
- **S（bench 信号）**：任一划分 `process − state`（`cascade_f1`）≥ 实验 01 在该划分的 `MDE` 且 CI 排除 0 → `S+`；全部划分 `|Δ| < MDE` → `S0`；任一划分 `state − process` ≥ MDE → `S−`。
- **C（覆盖机制）**：连锁键覆盖度 `process − state` ≥ 0.02 → `C+`，否则 `C0`。

决策：

| G1 | G2 | S | 决策 |
| --- | --- | --- | --- |
| 真 | 真 | S+ | **继续**：按原计划做实验 03、04；叙事"形成缺口存在，形成过程可弥补" |
| 真 | 真 | S0 | **继续，但改叙事**：缺口在形成侧，拆除级联基准不敏感。实验 03 仍做（成本 < 1 小时）；实验 09 的建造推演与形成侧指标升为 P0，实验 08（含失误的形成过程）升为 P0；Related Work 强调"成品评测会漏掉形成缺口"。若同时 `C0`，机制解释：形成数据对拆除级联没有覆盖增量 |
| 真 | 真 | S− | **先做实验 07（预算对等）**：process 少一半操作片段，先排除该混杂，再继续实验 03 |
| 真 | 假 | 任意 | 先修 shuffle 对照，再重训 `shuffle_s0` 与 `partial_s0`；H2 的结论暂缓 |
| 假 | — | 任意 | **停止**主实验。先查：process 形成帧的动作与帧是否对齐（`actions[e][t]` 是产生第 t 帧的动作）、同帧多动作编码、是否训练步数不足。确认无误后仍假：前提在当前环境不成立，转实验 08（更难的形成过程）重测 G1；仍假则按"负结果 / 环境设计问题"处理，不要强行写成果 |

## 6. 预期结果（先验判断，不是测量值）

- **G1 真**的概率较高（约 80%）：state 模型从未见过大量"同时放置多个方块"的建造转移，形成·放置 上应明显落后；操作类三者接近。
- **G2 真**的概率约 75%：shuffle 的形成转移是非物理跳变（00 §14 中 6,055 个"变化"，平均 9.3 格），在有序验证集上应明显更差。
- **C**：形成片段中物理引起变化的转移只占 9.6%，且 process 的操作片段减半，预计 `C0` 的概率约 60%；若 `C0` 与 `S0` 同时出现，要把"形成过程对拆除连锁没有帮助"作为明确发现，而不是缺点。
- **S**：与实验 03 的情景大致一致：A 20% / B 35% / C 35% / D 10%；但本实验的单种子读数只用于分流，不是结论。

## 7. 风险与备选

- 单种子的 `S` 读数噪声大：只用 `S+/S0/S−` 做**优先级分流**，所有分流路径都不会取消实验 03；论文结论一律来自实验 03 的 3（或 5）种子。
- 验证集与训练成品场景重叠会使探针偏乐观：`--gen-val` 的 `overlap.json` 必须为 0（有重复就剔除补足）。
- 覆盖键过于严格导致覆盖度整体很低、差异看不出：同时报告 3×3 与 5×5，并报告仅 3×3 的"无动作变化"（纯物理）子集。
- 预先登记的阈值（0.15 / 0.03 / 0.05 / 0.02）是先验猜测：若实验 01 的 `σ_seed` 显示这些阈值落在噪声内，可以**在运行本实验之前**统一调整并记录原因，之后不得改。
