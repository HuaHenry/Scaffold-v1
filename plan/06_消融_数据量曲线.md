# 06 消融：数据量曲线

优先级 P2 ｜ 对应假设：H1、H3 ｜ 公共约定见 `00`

## 1. 目标

改变训练 episode 数 `N ∈ {32, 64, 128, 256, 512}`，观察各条件的性能曲线，以及 process 相对 state 的增益是否随数据量增大而缩小。

## 2. 意义

回答"效应是小数据现象，还是随规模持续存在"。若增益随 N 增大而消失：形成过程是**数据效率**手段；若持续存在：它提供了成品数据没有的**信息**。两种结论对后续 3D 工作的意义不同。

## 3. 实验设计

- 数据：生成 512 个 episode 的训练集（00 §2：前 256 个与 `output/data` 逐位相同，pytest 断言）。
- 取前 N 个 episode：`train.py --episodes N --data output/data512`。
- **固定优化步数 6000**（不随 N 缩放），小 N 会重复多轮，可能过拟合；记录验证集指标并标出过拟合迹象。
- 4 条件 × 5 档 × 3 种子；N=256 复用实验 03 的 run（需确认 `output/data` 与 `output/data512` 前 256 个 episode 等价，不等价则重训并说明）。其余 4 档共 48 个新任务。
- 评测同实验 03（bench 不变）。

## 4. 实现（本实验独有部分）

```bash
python run.py --gen-train --data-dir output/data512 --episodes 512     # 约 30 分钟 CPU，可后台；可按 episode 用 multiprocessing 并行（保持输出顺序）
python -m exp.make_jobs data_scale
python -m exp.run_queue --jobs exp/jobs/data_scale.json --gpus 0,1,2,3 --eval-after
python -m exp.analysis.scaling --out results/scaling.json
```

`scaling.py`：每个条件画 `N -> 连锁 F1`（对数横轴，按划分分面）；每个 N 计算 process-state 差值及 CI；拟合 `连锁 F1 ~ a + b·log2(N)`，比较各条件斜率 b。产出图表：Fig.7 的一格。

## 5. 验收标准

1. `output/data512` 前 256 个 episode 与 `output/data` 逐位一致。
2. 每个（条件, N）有 3 个种子；缺失者标注。
3. 曲线总体随 N 不下降（允许噪声）；若 N=512 的 state 比 N=256 更差，检查数据或训练。

## 6. 预期结果（先验判断）

- 所有条件随 N 提升，N=32→64 提升最快，N>=256 趋于平台（场景只有 10 种、参数范围有限，模型很快记住模板）。
- process 相对 state 的差值：约 45% 随 N 增大而缩小（数据效率型），约 30% 基本不变（信息型），约 25% 随 N 放大。
- OOD 划分平台更低，且 N 增大对 OOD 的帮助小于对 `id`。

## 7. 风险与备选

- 时间紧时只做 N ∈ {64, 256, 512} × 4 条件 × 2 种子。
- 小 N 过拟合会让曲线非单调，此时报告验证集指标并说明。
