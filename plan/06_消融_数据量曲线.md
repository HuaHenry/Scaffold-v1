# 06 消融：数据量曲线

优先级 P2 ｜ 对应假设：H1、H3 ｜ 公共约定见 `00`

## 1. 目标

改变训练episode数，观察四条件的连锁F1随数据量如何变化，以及 `process − state` 的增益是否缩小、保持或扩大。

本版替代旧的32～512集、6,000步、生成 `data512` 并复用03端点的方案。直接复用03目前的81,920集冻结数据；不重新生成或筛选场景，不改物理规则。

## 2. 数据与档位

来源运行：`20261111-044057_four_conditions`。

- 训练：`game_code/output/data_v3_simple_train_hard_eval_81920`
- 验证：同目录的 `validation`
- 测试：同目录的 `bench.npz` 及 `bench.json`，共512个固定困难场景，每类128个。
- 五档：`N = 5120, 10240, 20480, 40960, 81920`。
- 同一档的四条件使用同一冻结数据中 `[0,N)` 的episode，档位之间前缀嵌套，不复制数组或生成新数据目录。
- 输入SHA1必须匹配03的 `audit.json`；保存各档不同成品数、重复episode数、场景类别计数、前缀清单摘要和转移预算。
- 这里只保证03当前冻结数据内部的嵌套前缀，不声称与早期256集数据逐位一致。

N是episode数，不是不同成品结构数；81920集包含重复成品，应同时报告实际不同成品数。

## 3. 等训练预算

四条件：`state/process/partial/shuffle`；训练种子默认 `0,1,2`。

| 项目 | 设置 |
|---|---|
| 每格更新数 | 94,400，与05当前等更新预算一致 |
| batch | 256 |
| 每格监督抽样数 | 24,166,400 |
| 抽样 | 所有合法video转移中均匀有放回抽样 |
| 模型 | dim384、depth8、heads6，沿用当前03/05模型 |
| 优化 | AdamW，lr0.0003→0.00003，warmup300，wd0.05 |
| 其他 | EMA0.999，change_weight8，unroll1，验证每500步及最后一步 |
| checkpoint | 最后第94,400步，保存原模型及EMA，评测EMA |
| 任务数 | 4条件 × 5档 × 3种子 = **60个新任务** |

验证只监控，不选模型。所有档位均从头训练，**不复用03最大N模型**：03采用五个完整epochs且选择验证最佳模型，与本次统一更新数、最终EMA协议不同。

| N | state/partial合法转移数 | process/shuffle合法转移数 |
|---:|---:|---:|
| 5120 | 286720 | 302080 |
| 10240 | 573440 | 604160 |
| 20480 | 1146880 | 1208320 |
| 40960 | 2293760 | 2416640 |
| 81920 | 4587520 | 4833280 |

保留原视频片段边界，不跨重置； `shuffle` 的乱序形成转移必须保留，不能改为只取 `cont=True`。有放回抽样次数不是完整epochs。不同N的每转移平均抽样次数不同，结果应解释为**固定训练预算下的数据量曲线**。

## 4. 实现与运行

代码：`preresearch/06_data_scale`；详细说明见该目录 `README.md`。

使用现有 `zhouqi` 环境，从项目根目录进入：

```bash
conda activate zhouqi
cd preresearch/06_data_scale
```

只读预检，不创建结果目录：

```bash
env -u FW_RUN bash run_all.sh --dry-run
```

四卡完整运行：

```bash
env -u FW_RUN bash run_all.sh --tag data_scale_final --gpus 0,1,2,3
```

先准备、不训练：

```bash
env -u FW_RUN bash run_all.sh --stage prepare --tag data_scale_final
```

续跑使用准备阶段打印的运行名：

```bash
bash run_all.sh --run <运行名> --stage train --gpus 0,1,2,3
bash run_all.sh --run <运行名> --stage analyze
bash evaluate_final.sh --run <运行名> --gpus 0,1,2,3
```

四卡分别处理独立任务，不是单模型四卡DDP。已提交训练与评测可复用；训练中断从第0步重训，不恢复优化器。修改数据来源、档位、种子或更新预算必须新建运行。

纯评测会先核验所有记录任务的最终权重，缺任一任务整体停止；不会重训或回退验证最佳模型。

## 5. 分析与输出

结果写入 `experiments/preresearch/06_data_scale/<运行名>/`：来源、前缀审计、任务表、训练配置、日志、checkpoint、完成记录及逐场景评测。

- 横轴 `log2(N)`，按四类测试分面绘制四条件连锁F1曲线，另画 `process − state` 增益曲线。
- 汇总 `cascade_f1/change_f1/cell_acc_mask/rank_acc/any_violation`，保留训练和验证准确率记录。
- 每个N计算 `process − state/partial/shuffle` 的配对差值。
- 拟合 `F1 = a + b·log2(N)`，b表示数据量每翻倍的变化；同时计算 `process − state` 等斜率差和最大N与最小N的增益差。
- 先对同场景的训练种子求平均，再进行10,000次配对场景bootstrap，给出95%区间；单独报告训练种子标准差，只有一个种子时为缺失而不是0。
- 默认要求所有格完整。显式使用 `--stage analyze --allow-incomplete` 时，只使用在全部N和四条件上完整的共同种子，列出缺失及未纳入格；若没有完整共同种子则停止。损坏的已提交结果仍报错。
- 输出 `data_scale.json`、`data_scale.md` 以及PNG/PDF图，保存输入和模型身份。

## 6. 验收

1. 来源文件全部匹配03冻结审计，验证与bench不变化；不生成新轨迹。
2. `0 < N ≤ 81920`，至少两档、递增不重复；禁止加载器静默截断超范围N。
3. 每条件实际使用N集，合法转移数为 `56N` 或 `59N`，所有条件使用同一episode范围。
4. 默认60个任务，所有格更新数、batch、学习率和模型一致；小N不缩短更新预算。
5. 训练完成核验配置、最终步数、样本预算、原模型/EMA可加载且有限、权重及完成记录身份。
6. 评测使用同一512场景且顺序一致，checkpoint身份一致，指标可由预测状态复核。
7. 区间和种子标准差不混淆；缺失条件不能当低分或冒充完整三种子。
8. 非单调结果如实记录，不作为代码验收失败，也不为符合先验修改结果。

## 7. 风险与简化运行

- 默认60个大模型任务，四卡最多并行四个，约15批；耗时需要根据实际吞吐重估，旧小模型5～15分钟估计不适用。
- 原加载器先解压全量NPZ再切前缀，小N也可能有较高CPU内存峰值；四卡并行前确认主机内存。全量每任务还需数据及模型显存，不做自动OOM降配。
- 小N重复暴露多，可能过拟合；训练/验证转移类型不同，不能仅凭准确率差值断言原因。
- 若先跑种子0：新建运行并传 `--seeds 0`，共20个任务。若简化三档： `--sizes 5120,20480,81920`；实际协议会写入运行，不能称完成默认60任务。
- 当前 `id` 仍是陌生困难结构测试；增益持续或缩小不单独证明“额外信息”或“仅数据效率”，结论限制在本次数据、规模范围与固定训练预算内。
