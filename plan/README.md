## 1. 一句话概述

**当前的世界模型（视频生成 / 交互式游戏模型）能复现世界上的物体及其运作规律，却没有见过这些物体"是怎么被一块一块造出来的"，因此不理解结构的依赖关系，也难以泛化到新结构和更逼真的因果。**

我们用一个**确定性的二维方块建造世界（FormWorld，Minecraft 风格）** 来检验这一点：它既是可玩的游戏，也是带精确真值的数据引擎。2D 是一个系列的第一篇，后续走向 3D Minecraft：**从几张照片 -> 重建三维结构 -> 多 agent 协作搭建出实体**。

## 2. 动机

### 2.1 观察

近两年的世界模型（视频生成模型、Genie 一类交互环境、GameNGen / DIAMOND / Oasis / MineWorld 等游戏世界模型）已经能生成高保真、动作可控的画面：它们"知道"房子、桥、塔长什么样，也能让物体按大致合理的规律运动和倒塌。但这些模型训练和评测时看到的几乎都是**成品世界**：已经存在的建筑、已经摆好的场景，以及它们的运作。

### 2.2 假设（本项目的核心，需要实验验证）

> **形成缺口（formation gap）：** 世界模型可以拟合"物体及其运作规律"，但没有学到"物体如何从零开始被构造出来"。而形成过程里恰恰包含成品里看不到的信息：**依赖顺序（先地基后梁）、临时支撑（脚手架）、承重关系，以及"缺了哪一步会发生什么"**。因此在新组合、新尺度和反事实问题上，只见过成品的模型会泛化得更差，也更容易生成违反结构规律的画面。

这个假设**目前没有直接证据**，需要靠文献佐证一部分（模型在组合泛化上的局限已有研究，见第 3.4 节），更需要靠我们自己的受控实验来检验。如果假设不成立，结论同样可以发表：它界定了形成过程数据在什么条件下有用或无用。

### 2.3 为什么是建造类沙盒

- **Minecraft 类环境是天然的"形成过程"数据源**：agent（或人）搭建的过程本身就是一段从无到有的视频，带有完整动作记录。这条视频既可以训练物理世界模型，也可以评测它是否理解结构。
- **真实视频做不了控制变量**：无法保证"只给成品"还是"给全过程"，也没有物理真值。
- **2D 起步的理由**：3D Minecraft 的视频模型训练开销大，且难以精确判定"是否违反物理"。2D 方块世界可以做到：规则明确、状态与图像无损往返、自动判定物理违规、数据秒级生成，几天内即可完成完整的受控实验。

### 2.4 研究问题

1. **RQ1** 看过逐块形成过程的模型，与只看成品的模型相比，对结构的反事实后果预测更好吗？
2. **RQ2** 增益来自**连续的因果转移**，还是仅仅因为见过更多中间画面？（用 partial / shuffle 消融）
3. **RQ3** 增益在分布外（新组合、更大尺度、多物体）是否更大？
4. **RQ4** 形成过程是否降低长程生成中的物理违规（浮空结构、结构压在沙 / 水 / 叶上、悬空的墙）？

### 3.2 叙事与可信边界

- **宏大叙事（引言和结尾）：** 世界模型要走向"能造世界"，必须理解**形成**，而不仅是**存在**；建造类沙盒是检验它的最干净的显微镜。
- **可信边界（实验章节）：** 在**一套离散规则的 2D 世界里**，我们受控地比较四种训练数据，并报告在哪些条件下形成过程有帮助、哪些条件下没有。不声称对真实物理或真实视频成立。

### 3.3 预期贡献（按审稿人最看重的顺序）

1. **一个可检验的新问题与假设：形成缺口。** 把"成品 vs 形成过程"形式化为受控的数据条件（state / process / partial / shuffle），其中 partial 与 shuffle 是排除"只是见过更多中间画面"的关键消融。
2. **FormBench-2D：** 带精确真值与物理违规检测器的评测集，含分布外划分（新组合、更大尺度、多物体）、成对反事实排序与背景层。
3. **受控实证研究：** 在相同模型、相同帧预算下比较四个条件，得到关于形成过程价值的第一手证据（无论正负）。
4. **FormWorld 环境与数据引擎：** 可玩的浏览器游戏（玩家搭建可被录制成数据），Python / JS 两套逐格一致的物理，精确渲染与解析，完整复现包。

### 3.4 相关工作（论文要覆盖的方向）

**游戏 / 交互式世界模型。** MineWorld（Microsoft，2025，Minecraft 实时交互世界模型，与 Oasis 对比；已核对）、Oasis（Decart / Etched）[待核]、GameNGen（DOOM）[待核]、DIAMOND（CS:GO 扩散世界模型）[待核]、Genie 系列 [待核]。共同点：训练数据是已有玩法的视频，没有显式研究"形成过程"。

**视频模型是否学到物理。** Kang 等，*How Far is Video Generation from World Model: A Physical Law Perspective*（ICML 2025；已核对）：在 2D 物理仿真上做受控实验，区分分布内、分布外和组合泛化，认为模型更像是按相似样本做检索，而不是抽象出规律。这是我们最接近的方法论先例：**同样用确定性 2D 模拟器做受控研究**；不同之处在于我们研究的是**数据的时间结构（成品 vs 形成）**，而不是模型规模和规律种类。Physics-IQ 等基准 [待核]。

**Minecraft 的 agent 与建造。** MineDojo、VPT、Voyager、Creative Agents（从想象图像建造）、CraftAssist / 3D-Craft（含按顺序搭建的人类数据集）、Project Sid（agent 社会）[均待核]。这些是第 II、III 篇的基础；本文的区别是：它们关注 agent 完成任务，我们关注**形成过程数据对世界模型理解结构的作用**。

**从照片到 3D 结构。** NeRF / 3D Gaussian Splatting / 多视图重建，体素化与 Minecraft 方块化 [待核]，用于第 III 篇。

**定位风险。** "2D 玩具世界"容易被质疑意义有限。应对：（a）重点放在**受控实验与评测基准**，而不是游戏本身；（b）与 Kang 等同类 2D 受控研究对齐，明确指出差异；（c）用 FormBench 的 OOD 划分和违规率给出清晰、可复现的结论；（d）用第 3.1 节的系列路线说明后续规模化计划。

### 4.2 世界与规则（离散沙盒规则，不是真实结构力学）

**两层网格。** 前景层 `g` 承重并碰撞；背景层 `back` 放墙、窗、火把、梯子、花，不承重、不碰撞。游戏世界 96 x 40；研究世界默认 28 x 22，可任意尺寸；v2 数据集用 56 x 28。

**21 种材料。** `EMPTY, GROUND, STONE, WOOD, LEAF, SAND, WATER, CLOUD, DIRT, GRASS, BRICK, GLASS, ROOF, DOOR, WALL, TORCH, LADDER, FLOWER, OPEN_DOOR, DOOR_TOP, OPEN_DOOR_TOP`。

**承重与悬挑。** 承重材料：地面、石、木、泥、草、砖、屋顶瓦、窗（前景形式）和门。支撑由广度优先搜索得到：从地面出发，竖直向上无损耗，横向每格消耗 1 点额度，各材料有最大悬挑长度：

| 材料 | 石 | 木 | 砖 | 屋顶瓦 | 窗(前景) | 泥 / 草 |
| --- | --- | --- | --- | --- | --- | --- |
| 悬挑 | 2 | 4 | 6 | 6 | 2 | 0 |

不受支撑的结构块每个 tick 下落一格，只能穿过空格或松散物质（与之交换位置），因此**结构块不会停在叶 / 沙 / 水上**。

**松散材料。** 叶：必须在木 4 格以内沿相邻格连通；沙：下落并斜向滑落；水：向下流，其次横向流向落差处。

**门。** 占两格，底部必须放在承重地面上；开启后仍参与结构支撑但不阻挡通行；地面被移除时整扇门一起下落。

**背景物件必须有依托（最新修复）。**
- 墙 / 窗：必须贴着实心方块（上下左右或同一格），或连着一片已有依托的墙；
- 火把 / 梯子：必须贴着实心方块或墙，梯子也可接在上下相邻的梯子上；
- 花：下方必须是草或泥；
- 依托消失后（拆方块、方块坠落、读档）失去依托的背景物件被清除。用连通性判断，不能靠两块墙互相悬挂。

**两种推进。** `tick()` 推进一步，用于动画与 v2 数据的逐帧生成；`step()` 连续 tick 到平衡并清理悬空背景，用于参考构造。

### 4.3 一致性与渲染

- `core.py` 与 `physics.js` 使用同一个线性同余随机数发生器与同样的洗牌顺序。测试对比随机前景动作序列的逐 tick 结果，以及随机前景 + 背景混合动作序列的最终前景 / 背景 / 每步成败。
- `render.py`：21 色平涂调色板。`compose(fg, bg)` 得到"玩家看到的"画面（有前景块显示前景，否则显示背景），`render_layers` 支持单帧或任意叠加的帧栈，`parse` 可无损还原。
- `painter.js` 是艺术化纹理渲染，仅用于游戏画面，不是精确编码。

### 4.4 游戏功能

建造（砖 / 木板 / 圆石 / 屋顶瓦 / 泥 / 草 / 叶 / 沙 / 水，背景墙 / 窗 / 火把 / 梯子 / 花，两格门）；玩家行走、跳跃、自动上一格台阶、爬梯子、`F` 飞行；Cottage 与 Workshop 蓝图（进度条和分组清单、"Watch it being built"自动搭建演示）；撤销 / 重做、存档 / 读档、网格线、缩放、小地图、昼夜、重力开关、JSON / PNG 导出、状态与动作录制。

### 5.3 四种训练条件（控制变量）

每个 episode 64 帧（`T=64`）。四个条件**共用同一个场景实例**，只有时间结构不同。

- **操作片段（operation clip，8 帧）**：第 1 帧是基础结构（重置帧，无动作）；第 2 帧施加一次干预并 tick 一次；其后 6 帧只 tick（观察坍塌 / 流动 / 沉降）。
- **形成片段（formation，32 帧）**：第 0 帧是空地形；之后把建造动作切成最多 27 段（每段若干个连续动作，平均 1.4 个 / 帧），每段后 tick 一次；末尾保留至少 4 帧只 tick，让结构沉降。因此整个建造过程（从无到有）都在这 32 帧里。

| 条件 | 帧构成（共 64） | 想隔离的因素 |
| --- | --- | --- |
| **state** | 8 个操作片段，基础 = 成品 | 基线：只见成品及其运作 / 坍塌 |
| **process** | 32 帧连续形成 + 4 个操作片段（成品） | 连续的形成转移 |
| **shuffle** | 与 process **完全相同的 32 帧**，随机打乱顺序（连续性标记为 False）+ 同样的 4 个操作片段 | 同样的画面，破坏时序因果 |
| **partial** | 8 个操作片段，基础 = 随机选取的**中间（未完工）结构** | 见过等量中间态，但没有任何连续形成转移 |

**设计取舍（需要知道）。**
- process / shuffle 用掉一半帧预算去看形成过程，所以它们看到的"成品上的运作"只有 state 的一半。如果 process 仍然更好，说明形成过程的价值超过了被牺牲的运作数据，这对 H1 是更严格的检验。
- 每帧都带 `cont[t]`：`True` 表示这一帧是上一帧的物理后继，`False` 表示场景重置 / 跳变。训练视频模型时应据此切分片段，不要把重置当作连续转移。
- process 与 state 在成品上使用**同一批干预**（state 的前 4 个片段的动作与 process 的 4 个操作片段逐帧相同，有测试）。

**干预（`pick_event`）：** 55% 移除承重块（石 / 木 / 砖 / 屋顶瓦）；10% 移除背景物；7% 开关门；8% 挖掉结构下方的草；其余为在空中放置石 / 沙 / 水 / 木。

### 5.4 FormBench-2D

每个样本 = 一个已沉降的结构 + **两个候选干预** + 各自 32 tick 的真值未来。每个划分 128 个样本，共 512。

| 划分 | 含义 | 场景 |
| --- | --- | --- |
| `id` | 分布内 | 10 种训练场景，基本参数 |
| `combo_ood` | 新组合（训练中从未同屏出现） | cottage+tree、hut+tower、bridge+dune、watchtower+pond、arch+garden、cottage+watchtower |
| `scale_ood` | 更大尺度 | 高塔、长桥（跨度 10-13）、宽拱、Workshop 式宽屋、高 watchtower |
| `multi_ood` | 三物体同屏 | tower+bridge+tree、cottage+watchtower+garden、hut+arch+dune、cottage+tree+pond |

**干预候选**：承重方块、结构下方的土、围着水的土。每个场景评估 16 个候选，取**效果差异最大**的一对；其中效果更大的排在第 0 位。

**标签 `labels`**：未来最终状态相对初始状态的变化率 = 变化格数 / 关注格数，关注格 = 任一状态中地面以上有方块或背景物的格子，加上任何发生变化的格子（避免大片空天空稀释信号）。

**任务与指标**

| 任务 | 做什么 | 指标 |
| --- | --- | --- |
| collapse | 预测干预 0 之后沉降的状态 | 全图格准确率、关注区格准确率、结构 IoU、变化 F1（`score_outcome`） |
| counterfactual | 判断两个干预谁的变化更大 | 排序准确率，仅用 `rank_valid`（标签差 >= 0.03）的样本 |
| long_rollout | 看 32 帧预测的最后一帧是否违反物理 | `check_violations(fg, bg)`，真值为 0；包含悬空背景物 |

**质量保障**：生成时丢弃真值未在 32 tick 内沉降的候选、含违规的候选，以及与训练成品逐格相同的场景（`id` 划分是真正的留出，泄漏数 0）。

### 5.5 文件格式（`output/data/`，当前总计约 3 MB）

| 文件 | 内容 |
| --- | --- |
| `train_{state,process,partial,shuffle}.npz` | `fg` `bg`：`uint8 [256,64,28,56]`；`cont`：`bool [256,64]`；`phase`：`int8 [256,64]`（0 形成，1 操作）；加 `--frames` 时另含 `frames [256,64,56,112,3]` |
| `train_*_actions.json` | `actions[episode][frame]` = 该帧开始前施加的动作列表；`extra`：shuffle 的 `order`、partial 的 `picks` |
| `train_finals.npz` / `train_scenes.json` | 每个 episode 的成品、场景种类 / 参数 / 动作数 / 切段大小 / 是否沉降 |
| `train_summary.json` | 各条件的帧数、连续转移数、重置帧数、形成帧数 |
| `bench.npz` | `ctx_fg ctx_bg [512,28,56]`；`fut_fg fut_bg [512,2,32,28,56]`；`labels settled_at n_changed violations [512,2]`；`rank_valid [512]`；`split_ids [512]` |
| `bench.json` | 划分定义、场景、两个干预的动作、任务与指标说明、被拒绝的尝试数 |
| `audit.json` | 审计报告 |

上下文为"成品静止"，可把 `ctx_*` 重复 4 帧作为输入。图像用 `render_layers(fg, bg, 2)` 即可批量得到。

### 5.6 实际生成结果（seed 0，`python run.py --data`）

**训练集：256 episodes x 64 帧 = 16,384 帧 / 条件。**

| 条件 | 连续转移 | 重置帧 | 形成帧 | 前景结构格 / 帧 | 背景格 / 帧 |
| --- | --- | --- | --- | --- | --- |
| state | 14,336 | 2,048 | 0 | 241.5 | 5.2 |
| process | 15,104 | 1,280 | 8,192 | 239.3 | 3.9 |
| shuffle | 7,168 | 9,216 | 8,192 | 239.3 | 3.9 |
| partial | 14,336 | 2,048 | 0 | 235.2 | 1.2 |

- 场景分布：garden 36、watchtower 34、pond 28、bridge 28、dune 26、cottage 25、hut 21、arch 20、tower 19、tree 19。
- 平均每个场景 26.3 个建造动作（最多 97），平均每帧 1.4 个动作（最大 4）；所有 256 个形成过程都在 32 帧内沉降。
- process 与 shuffle 的前景 / 背景材料直方图完全相同（同一批帧）。
- partial 的背景物明显更少（1.2），因为中间态大多尚未建墙，这是该条件的设计特征。

**FormBench：512 样本，泄漏 0，真值违规 0。**

| 划分 | n | 平均标签 | 干预 0 引起坍塌占比 | rank_valid 占比 | 平均沉降 tick | copy-last 关注区格准确率 | copy-last 结构 IoU |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | 128 | 0.190 | 94.5% | 81.2% | 0.75 | 0.764 | 0.874 |
| combo_ood | 128 | 0.066 | 95.3% | 87.5% | 0.76 | 0.891 | 0.914 |
| scale_ood | 128 | 0.149 | 100% | 99.2% | 0.96 | 0.752 | 0.792 |
| multi_ood | 128 | 0.045 | 99.2% | 64.8% | 0.79 | 0.924 | 0.941 |

### 6.6 成功标准与叙事预案

- **强成功：** process 在 OOD 划分上显著优于 state、partial、shuffle 且违规更低。叙事："形成缺口真实存在，形成过程可以弥补"。

- **负结果：** 无差异。叙事：在 2D 规则世界与小模型下形成缺口不显著，并分析原因（动态太短、模型太小、copy-last 基线太强）。这样的论文更难中，但应如实写。
- **关键风险：** 每次干预引起的变化很小（平均 3-10 格），copy-last 在格准确率上已经很高。应对：主指标用变化 F1 / 排序准确率 / 违规率；必要时增加更大、更连锁的结构。

## 9. 已知局限

1. **规则是离散玩具规则**，不是真实力学。结论只能解释为"在这套规则里"。
2. **每个 tick 最多下落一格**，所以多数坍塌在 1-2 个 tick 内完成（平均沉降 tick 约 0.75-0.96）。时间维度的动态较短；若要更长的动态，可考虑更高的建筑或连锁结构。
3. **copy-last 基线很强**（关注区格准确率 0.75-0.92），因为一次移除通常只改变少数格子。需要靠变化 F1、排序准确率、违规率来区分模型，而不是靠格准确率。
4. **multi_ood 的标签偏小、rank_valid 只有 65%**：多物体场景里一次干预只影响一处，被其余静止结构稀释。建议加局部指标。
5. **bench 的场景分布不均衡**：为保证有两个可区分且沉降的干预，dune / pond / tree / garden 被拒绝得更多，`id` 里 tower、bridge、arch、watchtower 占比较高（见 `audit.json`）。
6. **partial 的背景物很少**，因为中间态里墙还没建；它是一个有意的特征，也意味着 partial 与其他条件在背景层上不严格等量。
7. **场景由程序生成**，多样性有限，模型可能记住模板。靠 OOD 划分与后续扩充场景缓解。
8. **hut 除门朝向外没有随机变化**，可以后续加入。
9. **艺术化渲染不可解析**，游戏截图不能当训练输入；需要精确状态时用数据集或游戏录制出的 JSON。
10. **背景清理的副作用**：拆掉孤立墙的中间一格，连在断开那头且无其他依托的墙会一起消失，所以录制数据里一次动作可能改变多格。
11. **浏览器录制上限 1500 次转移**。
