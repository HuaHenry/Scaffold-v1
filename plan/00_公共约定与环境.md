## 3. 数据规格（v2，`output/data/`，seed 0）

grid：`H=28, W=56`，草地行 `SURF=24`，基岩行 27。材料 id 0–20（见 `core.py`）：EMPTY=0, GROUND=1, STONE=2, WOOD=3, LEAF=4, SAND=5, WATER=6, CLOUD=7（未使用）, DIRT=8, GRASS=9, BRICK=10, GLASS=11, ROOF=12, DOOR=13, WALL=14, TORCH=15, LADDER=16, FLOWER=17, OPEN_DOOR=18, DOOR_TOP=19, OPEN_DOOR_TOP=20。前景层含 {0–6, 8–13, 18–20}，背景层含 {0, 11, 14–17}。

训练集 `train_{state,process,partial,shuffle}.npz`（每个 256 episode × 64 帧）：

| 键 | 形状 / 类型 | 含义 |
| --- | --- | --- |
| `fg`, `bg` | `uint8 [256,64,28,56]` | 前景 / 背景层 |
| `cont` | `bool [256,64]` | `cont[e,t]=True`：第 t 帧是第 t-1 帧的真实物理后继；False：重置 / 跳变 |
| `phase` | `int8 [256,64]` | 0 = 形成片段，1 = 操作片段 |

`train_{c}_actions.json`：`{"actions": [episode][frame] -> list[dict]}`。**`actions[e][t]` 是产生第 t 帧的那次 tick 之前施加的动作**（第 t-1 帧 -> 第 t 帧使用 `actions[e][t]`）。动作 `{"type": place|remove|interact|noop, "x","y","material","layer": front|back}`；形成片段每帧至多 4 个动作，操作片段每帧至多 1 个。`extra[e]`：shuffle 含 `order`，partial 含 `picks`。

帧布局：state / partial = 8 个操作片段 × 8 帧；process / shuffle = 帧 0–31 形成片段（shuffle 为打乱顺序）+ 帧 32–63 的 4 个操作片段。操作片段 = 第 0 帧基础结构（重置）+ 第 1 帧施加干预并 tick + 6 帧纯 tick。其他文件：`train_finals.npz`（成品 `fg,bg`）、`train_scenes.json`、`train_summary.json`（含 `layout`）、`audit.json`。

FormBench `bench.npz`（512 样本，每划分 128；`split_ids` 0–3 对应 `bench.json["splits"] = [id, combo_ood, scale_ood, multi_ood]`）：

| 键 | 形状 | 含义 |
| --- | --- | --- |
| `ctx_fg`, `ctx_bg` | `[512,28,56]` | 已沉降的初始结构 |
| `fut_fg`, `fut_bg` | `[512,2,32,28,56]` | 两个候选干预各自 32 tick 的真值 |
| `labels` | `float32 [512,2]` | 变化率；**索引 0 的效果总 >= 索引 1** |
| `settled_at`, `n_changed`, `violations` | `int16 [512,2]` | 稳定 tick、终态变化格数、终态违规数（全为 0） |
| `rank_valid` | `bool [512]` | 两个标签差 >= 0.03 |

`bench.json["interventions"][i][k]` 是动作 dict；`scene_kinds[i]`、`scenes[i]` 给出场景组成。

## 4. 编码约定（所有模型、所有实验一致）

状态：`fg, bg` 为 `[H,W]` 类别 id；模型有两个输出头，各 21 类。

动作 -> action map（`common.encode_actions(actions, H, W) -> int64 [H,W]`）：
- `type_idx`：place=0, remove=1, interact=2；noop 忽略。
- `material_eff`：place 取其材料；**remove 和 interact 一律取 0**（防止 remove 的 material 字段泄漏意图）。
- `layer_idx`：front=0, back=1。
- 单元格 token：无动作为 `0`；否则 `1 + ((type_idx*21 + material_eff)*2 + layer_idx)`，词表 127。同格多动作取最后一个；动作顺序不编码（形成片段同帧多动作的先后信息会丢，已知局限）。

转移样本：`(fg_{t-1}, bg_{t-1}, actions[t]) -> (fg_t, bg_t)`，马尔可夫一步（引擎是马尔可夫的，默认上下文 K=1）。

## 5. 训练协议（必须同时实现，实验指明用哪一种，默认 `video`）

问题：shuffle 的形成帧 `cont` 全为 False；若训练只用 `cont=True` 的转移，shuffle 就退化成"只有操作片段"，失去对照意义；真实视频模型也不知道帧序被打乱。

| 协议 | 训练转移集合 | 用途 |
| --- | --- | --- |
| `video`（默认） | 把 episode 切成**视频片段**，片段内所有相邻帧对都当转移，不看 `cont`；重置帧不当转移。片段边界从 `train_summary.json["layout"]` 读取：state / partial 每 8 帧一段；process / shuffle 为 `[0,F)` 一段（shuffle 即使被打乱也当作一段视频），其后每 8 帧一段 | 主结果，模拟"拿到什么视频就学什么" |
| `causal` | 只用 `cont[e,t]=True` 的转移 | 补充：证明 shuffle 在 `causal` 下等价于只有操作片段 |

转移数（T=64, F=32）：state / partial 每 episode 8×7 = 56（共 14,336）；process / shuffle 的 `video` = 31 + 4×7 = 59（共 15,104，其中 shuffle 的 7,936 个形成转移是非物理跳变）；`causal` 下 process = 15,104，shuffle = 7,168。实现 `common.make_pairs(data_dir, condition, protocol) -> int32 [N,2]`（`(episode,t)` 表示 t-1 -> t），pytest 断言上述数字。

## 6. 指标（`exp/metrics.py`）

记 `S=(fg0,bg0)` 初态，`P` 预测终态，`T` 真值终态，`A` 干预覆盖的格集合（动作 `(x,y)`；对门的 `interact` 或 `remove`，用 `FormWorld.door_base` 加入门的上下两格）。

```python
changed(a, b) -> bool[H,W]            # (a.fg != b.fg) | (a.bg != b.bg)
score_sample(P, T, S, A) -> dict:
  cell_acc_all, cell_acc_mask, structure_iou, change_f1   # 复用 datasets.score_outcome，禁止重写
  cascade_f1       # F1(pc & ~A, tc & ~A)；两者都空记 1.0
  cascade_f1_nonempty   # 仅在 tc & ~A 非空的样本上聚合
  cascade_recall   # |pc&tc&~A| / max(1,|tc&~A|)
  exact            # 预测与真值整个 (fg,bg) 完全相同
  violations, any_violation   # check_violations(P.fg, P.bg, bg) 之和
```

- **主指标是 `cascade_f1`**（除被拆那一格以外的连锁变化），其次 `change_f1`、`cell_acc_mask`、`rank_acc`、`any_violation`；`exact` 仅辅助。
- **排序准确率**：对每个样本**独立**预测干预 0 和 1 的终态，各自计算 `datasets.change_rate(S, P_k)`，`rank_acc = mean([p0>p1] + 0.5·[p0==p1])`，仅 `rank_valid=True` 的样本。不能把两个干预同时输入，也不能把顺序当输入。随机 / 恒定预测应得 ≈0.5（pytest）。
- 终态：`final_fp`（推演到定点或 32 步，先到者，主指标用）与 `final_32`（恒取第 32 步，衡量漂移）。
- 短程：另报第 1 步、第 4 步的 `change_f1` / `cascade_f1`（真值取 `fut_*[i,k,0]`、`[i,k,3]`）。
- 质量守恒误差 `mass_error(P, T)`：每种材料格数差的绝对值之和（实验 09 用）。

## 7. 基线（`exp/baselines.py`）

接口：`predict(ctx_fg, ctx_bg, action, seed=0) -> (fg_final, bg_final)`；`predict_traj(...) -> (fg[32,H,W], bg[32,H,W])`。

| 名称 | 定义 |
| --- | --- |
| `copy_last` | 返回初态（"什么都不会发生"） |
| `apply_edit` | `FormWorld(...).apply_action(...)` 后不 tick、不清背景（只执行动作的字面效果） |
| `oracle_reseed` | 真实引擎、不同随机种子 12345，`datasets.rollout` 推演 32 步；受沙 / 水随机性限制，是实际上限 |
| `random_physics` | 动作换成同一结构上其他承重块的 `remove`（`candidate_interventions` 去掉真实目标，`random.Random(i)`），再用真实引擎推演 |

**已测得的基线数值**（v2 数据，seed 0，仅干预 0；实现后必须复现，误差 <= 0.002）：

| 划分 | copy_last 关注区格准确率 | copy_last 结构 IoU | apply_edit 变化 F1 | apply_edit 连锁 F1 | oracle_reseed exact | 有连锁样本比例 | 平均连锁格数 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | 0.764 | 0.874 | 0.541 | 0.055 | 0.961 | 0.945 | 2.70 |
| combo_ood | 0.891 | 0.914 | 0.370 | 0.039 | 0.992 | 0.961 | 5.52 |
| scale_ood | 0.752 | 0.792 | 0.315 | 0.000 | 1.000 | 1.000 | 8.56 |
| multi_ood | 0.924 | 0.941 | 0.329 | 0.008 | 0.984 | 0.992 | 5.97 |

解读：copy_last 的变化 F1 恒为 0、排序 ≈0.5；apply_edit 的连锁 F1 ≈0，即"没有物理理解"的签名；训练出的模型必须在连锁 F1 上显著高于 apply_edit，才算学到物理。

## 8. 模型：GridFormer（`exp/model.py`，所有条件、所有实验共用）

输入 `fg[B,H,W], bg[B,H,W], act[B,H,W]`（long）：

```
cell_emb = E_fg(21,96)[fg] + E_bg(21,96)[bg] + E_act(127,96)[act]         # [B,H,W,96]
patch    = 2x2 合并拼接 -> [B,14,28,384] -> Linear(384,384)                # 392 token
pos      = 可学习二维绝对位置嵌入 14x28（高度信息对重力很重要）
blocks   = 8 x TransformerBlock(d=384, heads=6, mlp=4x, pre-LN, GELU, 无 dropout, SDPA)
head     = LayerNorm -> Linear(384, 4*(21+21)) -> 还原为每格 fg / bg 两组 21 类 logits
copy bias: logits_fg += a_fg * onehot(fg_prev); logits_bg += a_bg * onehot(bg_prev)   # a 可学习，初值 3.0
```

约 14–15 M 参数。接口：`forward(fg,bg,act) -> (logit_fg[B,21,H,W], logit_bg[B,21,H,W])`；`step(...)`：argmax 的下一状态。

## 9. 训练配置（`exp/train.py`，冻结）

| 项 | 值 |
| --- | --- |
| 损失 | 逐格交叉熵（fg 头 + bg 头）；变化格权重 8、未变化格权重 1，按权重和归一化（变化格 = 目标与上一状态不同的格，任一层） |
| 优化器 | AdamW，lr 3e-4，betas (0.9,0.95)，wd 0.05；线性 warmup 300 步，余弦衰减到 3e-5 |
| batch / 步数 | 256 / **固定 6000 步**（各条件步数相同，不按 epoch） |
| 精度 / EMA | bf16 autocast，梯度裁剪 1.0；EMA 0.999，评测用 EMA |
| 采样 | 每步从该条件的 pairs 均匀有放回采样 |
| 增强 / 展开 | 默认无；`--unroll K`（默认 1）：额外 K 步自回归展开，仅在 §13 漂移检查失败时对**所有条件**统一开启 |
| 种子 | `--seed` 控制初始化与采样；数据不随 seed 变（固定数据集） |

超参来自 `exp/configs/frozen.json`（§13 的一次性调参产生），之后不得针对单个条件调整。

## 11. 队列、产物、随机性

```bash
python -m exp.make_jobs <实验名>      # 生成 exp/jobs/<实验名>_steps<步数>.json（含带时间戳的结果目录）
python -m exp.run_queue --jobs exp/jobs/<实验名>_steps6000.json --gpus 0,1,2,3 --eval-after
```

`jobs.json`：`[{"name","cmd":[...],"out"}]`，`out` 是相对结果根目录（§11.1）的结果文件夹，生成任务清单时就确定（含时间戳）；清单已存在则复用，因此重跑同一条队列命令即续跑同一批文件夹。每张 GPU 同时只跑 1 个任务，子进程设 `CUDA_VISIBLE_DEVICES`；`out/done.json` 存在则跳过；失败写 `out/failed.json` 并继续；`--eval-after` 在训练后串联评测。

### 11.1 结果目录与命名（预实验必须遵守；后续实验沿用同一规则，换 `experiments/<阶段>/` 根目录）

**路径总则（全局，所有代码、配置、文档、输出文件都适用）：禁止写死绝对路径**（含 `/Users/…`、`/home/…`、盘符、`/tmp/…`），项目整体要能被整体移动 / 拷贝到另一台机器后原样运行。
- `<项目根>` = 环境变量 `FW_PROJECT`，否则从代码所在位置向上找到第一个含 `game_code/` 的目录（`common.PROJECT`）。代码、数据、结果的默认位置都由它推算：`<项目根>/game_code`（`FW_GAME_CODE`）、`<项目根>/game_code/output/data_v3`（`FW_DATA`）、`<项目根>/game_code/output/data_val_v3`（`FW_VAL`）、`<项目根>/experiments/preresearch`（`FW_RESULTS`）。需要换位置时只设这些环境变量，不改代码。
- 命令行参数里的相对路径：输入路径先相对实验代码目录、再相对 `<项目根>`；结果路径相对结果根目录；绝不相对 shell 当前目录。
- 写进磁盘的任何内容（`config.json`、`meta.json`、`eval.json`、`failed.json`、任务清单、表格、文档）里的路径一律用 `common.rel(path)`：项目内的写成相对 `<项目根>` 的路径（结果目录内的写成 `<results>/…`），不写绝对路径。
- 文档里用 `<项目根>/…` 或相对路径。提交 / 迁移前检查：`grep -rnE "/Users/|/home/|/tmp/" <项目根> --exclude-dir=.venv --exclude-dir=output`，除本总则里的示例外必须无输出。

**位置。** 预实验的所有运行结果（训练、评测、基线、分析、检查、调参、图表）只写到：

```
<项目根>/experiments/preresearch/<实验目录>/<结果文件夹>/
```

- `<实验目录>` = 实验编号加名称，每个实验一个：`00_common`（§13 的前置检查与调参，各预实验共用）、`01_pilot_validity`、`02_...`。只有该实验自己的结果放在它的目录里。
- 结果根目录由 `common.RESULTS_ROOT` 给出（环境变量 `FW_RESULTS` 可覆盖）。代码里不得再写 `runs/`、`results/` 这样的相对路径，也不得把结果写进代码目录或 `game_code/`。
- **不是结果、不放这里的东西**：代码、`exp/jobs/*.json` 任务清单、`exp/configs/frozen.json`（配置）、数据集（`game_code/output/data_v3`、验证集 `data_val_v3`）。

**命名。** 同一个实验的多次 / 多种运行各占一个文件夹，名字格式固定：

```
<YYYYMMDD-HHMMSS>_<类型>_<名称>_<设置>
```

- 时间戳（本地时间）必须在最前面，这样按名字排序就是时间顺序；同一批任务（一次 `make_jobs`）共用一个时间戳。
- `<类型>`：`train`（训练及其自带评测）、`baseline`、`analysis`、`precheck`、`freeze`；以后新增类型按同样风格。
- `<名称>`：逻辑 id，沿用旧的 run 命名 `{condition}_s{seed}`，变体加中缀（`state_n64_s0`、`process_f16_s0`）；基线用基线名；分析用实验名。
- `<设置>`：能把这次运行与其他运行区分开的关键设置，用 `_` 连接，不含空格和斜杠。训练固定为 `ep<episode数>_<协议>_steps<步数>_bs<batch>_lr<lr>_cw<变化格权重>_d<深度>`（`unroll>1` 时追加 `_unr<K>`；实验自有的变量，如形成帧数 F、占比、失误率 p，追加在后面并写进 `meta.json`）。基线为 `bench-<bench 所在目录名>`（部分评测追加 `_first<N>` 或划分名）。分析为 `steps<步数>_boot<次数>_<指标口径>`。
- 例：`20261104-173012_train_state_s0_ep256_video_steps6000_bs256_lr0.0003_cw8_d8`、`20261104-181530_baseline_copy_last_bench-data_v3`、`20261104-190244_analysis_pilot_validity_steps6000_boot10000_cascade_f1`。
- 文件夹名只给人看。**程序按 `meta.json` 查找，不解析文件夹名。**

**登记。** 每个结果文件夹必须有 `meta.json`：`{"id","kind","exp","name","created","settings":{...}}`，`settings` 含所有区分设置（`steps`、`episodes`、`seed`、`lr` 等），由 `common.write_meta` 写入。查找用 `common.find_latest(id, kind, exp, require, match)`：返回满足 `settings` 条件、且含 `require` 文件（如 `done.json`、`eval_samples.npz`）的**最新**文件夹。分析和后续实验用它按“逻辑 id + 设置”取输入，不得写死某个时间戳。不同实验共用的训练（如 01 的 `state_s0..s2` 与 03）靠这种查找复用，不复制文件夹。分析结果的 `meta.json` 和输出 json 必须记录它实际读取了哪些文件夹（`inputs`）。

**文件夹内容。**
- `train`：`meta.json`、`config.json`、`train_log.jsonl`、`ckpt.pt`、`done.json`、`eval.json`、`eval_samples.npz`、`train.log`、`eval.log`（失败时 `failed.json`）。
- `baseline`：`meta.json`、`eval.json`、`eval_samples.npz`。
- `analysis`：`meta.json`、`<实验名>.json`、`<实验名>.md`，图放在其中的 `figs/`（PDF + PNG，见 §16）。
- `precheck` / `freeze`：`meta.json`、`precheck.json` / `frozen.json`。

**不得覆盖。** 每次运行新建文件夹，永不覆盖旧结果；同名冲突时自动在文件夹名末尾加 `-2`、`-3`。部分评测（`--limit`、`--splits`）写成带后缀的文件（如 `eval_first3.json`）。基线的部分评测另建文件夹，并在 `settings` 里标出 `limit` / `splits`，分析按 `limit=None, splits=all` 过滤。冒烟测试（步数不是正式值）同样落在自己的文件夹里，靠 `settings.steps` 与正式结果区分；分析必须显式按 `steps` 过滤。

**续跑。** 队列任务的文件夹在 `make_jobs` 时就确定；同一份任务清单重复运行会跳过已有 `done.json` 的文件夹。要开一批新的结果：`make_jobs ... --new`（新时间戳、新文件夹）。

**旧路径对照。** 其他文件里写的 `runs/main/X`、`runs/pilot/X`、`runs/{exp}/{name}` 是逻辑名，一律读作“`experiments/preresearch/<实验目录>/` 下 id 为 `X` 的 `train` 结果”。`results/{exp}.json`、`results/tables/{exp}.md`、`results/figs/{exp}_*` 读作“该实验目录下最新的 `analysis` 结果文件夹里的 `{exp}.json`、`{exp}.md`、`figs/`”。`results/baselines/*` 读作 `baseline` 结果。`results/compute.md`、`results/precheck.json` 放进 `00_common` 下对应类型的文件夹。冲突以本节为准。

随机性：模型种子 `{0,1,2}`；bootstrap 固定 `numpy.random.default_rng(12345)`；同参数同种子的前 200 步 loss 相差 < 1e-4（bf16 容差，pytest 说明）。

## 12. 统计与汇总（`exp/aggregate.py`）

- 先对每个条件的 3 个种子取**逐样本预测指标的平均**，再在样本层面做配对 bootstrap（10,000 次），报告差值的 95% CI；另报各指标的种子间标准差。
- 比较对：process-state、process-partial、process-shuffle、state-shuffle、partial-state。每个指标、每个划分都报；同时给原始 CI 和 Holm 修正后的结论。
- 主表：行 = 条件（含 4 个基线），列 = {id, combo_ood, scale_ood, multi_ood} × {cascade_f1, change_f1, structure_iou, cell_acc_mask, rank_acc, any_violation}，单元格 `均值 ± 种子 std`，输出 Markdown 与 LaTeX。
- 论文里的每个数字都由 `aggregate.py` 从 `eval.json` 产生，不手填。

## 13. 前置检查与一次性调参（正式实验前必须完成，11-05 内）

1. 编码往返；`make_pairs` 转移数等于 §5 的数字。
2. 过拟合：只用 1 个 episode 训练 500 步，该 episode 转移上变化格准确率 >= 0.99。
3. 稳定性：用 bench 初态做 32 步 noop 推演，状态不变的比例 >= 0.99。
4. **击穿基线**：用 `state` 完整训练 6000 步，在验证集和 bench `id` 上，连锁 F1 必须显著高于 apply_edit（预期 > 0.3；< 0.15 则先查损失权重、动作编码、学习率，不要继续跑其他实验）。
5. 确定性：同种子前 200 步 loss 相差 < 1e-4。
6. 漂移：state 模型的 `final_32` 与 `final_fp` 的 `exact` 差距 < 0.05；否则对**所有条件**统一加 `--unroll 2` 并重做第 4 项。
7. 调参只允许一次，只用 `state` 条件 + 验证集（**不用 bench**）：lr ∈ {1e-4,3e-4,1e-3}、变化格权重 ∈ {4,8,16}、深度 ∈ {6,8}，最多 18 组，每组 1 个种子（4 卡并行约 30–60 分钟）；结果写入 `exp/configs/frozen.json` 并提交。

以上只检查工程正确性。**假设本身与评测灵敏度由预实验检验，必须在主实验之前完成：** 实验 01（基准有效性、阳性 / 阴性对照、噪声底与 MDE）与实验 02（形成缺口存在性、覆盖度、信号读数与决策表）。它们的任务产物与实验 03 共用（同名 `out` 目录有 `done.json` 则跳过）。
