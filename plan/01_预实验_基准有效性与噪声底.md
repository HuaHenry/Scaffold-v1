# 01 预实验：基准有效性与噪声底

优先级 P0（主实验的前置）｜ 对应：支撑 H1–H4 的所有结论 ｜ 前置：`00` §13 全部通过 ｜ 公共约定见 `00`（指标 §6、基线 §7、训练 §9、统计 §12）

## 1. 目标

在花算力做主实验前，回答一个问题：**FormBench + 当前统计流程，能不能可靠地检测出我们预期大小的差异？** 具体拆成四件事：

1. **指标有区分度**：基线与训练模型在主指标 `cascade_f1` 上按预期排序，指标没有饱和或塌缩。
2. **阳性对照**：已知必然有效的操作（增加训练数据量）能被 bench 检出，并给出"数据量翻倍 ≈ 多少个 cascade F1 点"的标尺。
3. **阴性对照（A/A 检验）**：同一条件、不同种子组之间，统计流程不能报出"显著差异"；检验配对 bootstrap 是否低估训练随机性。
4. **噪声底与最小可检出效应（MDE）**：给出每个划分上种子间 std 与 MDE，决定主实验需要几个种子、要不要第二份 bench。

## 2. 意义

主实验（实验 03）预期四个条件只差几个百分点（见其 §6）。如果种子噪声或 bench 样本量本身就有同量级的波动，任何"process > state"的结论都不可信；反过来，如果 bench 连数据量翻倍都检不出来，说明评测对"结构理解"不敏感，需要先改评测而不是改假设。本实验把"实验失败"与"评测不灵"分开，并把 MDE 写进论文的统计方法一节。

## 3. 实验设计

全部使用条件 `state`（避免提前看到假设相关的对比），协议 `video`，冻结超参，bench 不变。

| 组 | 训练 episode 数 | 种子 | 位置 | 新任务数 |
| --- | --- | --- | --- | --- |
| `state_s0..s2` | 256 | 0,1,2 | `runs/main/`（与实验 03 共用） | 3 |
| `state_s3..s5` | 256 | 3,4,5 | `runs/pilot/` | 3 |
| `state_n64_s0..s2` | 64（`--episodes 64`，前缀） | 0,1,2 | `runs/pilot/` | 3 |
| `state_n16_s0..s2` | 16 | 0,1,2 | `runs/pilot/` | 3 |

共 12 个任务（4 卡约 3 轮，< 1 小时）。步数固定 6000，数据量不同则 epoch 数不同，这是有意的（数据量是自变量）。

分析（均在 `id`、`combo_ood`、`scale_ood`、`multi_ood` 四个划分上，主指标 `cascade_f1`，辅以 `change_f1`、`rank_acc`）：

- **A. 排序检查**：`copy_last`、`apply_edit`、`random_physics`、`state_s*`、`oracle_reseed` 的均值与 95% CI，预期严格递增。
- **B. 阳性对照**：`n256 − n64`、`n64 − n16`、`n256 − n16` 的配对 bootstrap 差值与 CI；并把差值换算成"每翻倍 x 个点"。
- **C. A/A 检验**：把 6 个 `state` 种子分成 {0,1,2} 与 {3,4,5} 两组，按 00 §12 的流程比较；重复所有 10 种 3+3 划分（`C(6,3)/2`），统计"CI 排除 0"的比例，应 ≈ 名义水平（5%），不应明显偏高。
- **D. 噪声底与 MDE**：`σ_seed` = 6 个种子在每个划分上 `cascade_f1` 均值的标准差；`SE_boot` = 配对 bootstrap 差值的标准差。近似 `MDE ≈ 2.8 × sqrt(SE_boot² + 2·σ_seed²/3)`（80% 功效、双侧 5%，每组 3 种子）。
- **E. 形成数据使用核查**（只检查管线，不比较结果）：对 `process` 与 `shuffle`，统计一次训练中每个 batch 内形成转移的平均占比，应 ≈ 31/59 = 52.5%（`video`）；写入一个短 `train` 运行即可，不属于上述 12 个任务。

## 4. 实现（本实验独有部分）

```bash
python -m exp.make_jobs pilot_validity      # 生成 exp/jobs/pilot_validity.json（12 个任务）
python -m exp.run_queue --jobs exp/jobs/pilot_validity.json --gpus 0,1,2,3 --eval-after
python -m exp.analysis.pilot_validity --out results/pilot_validity.json --table results/tables/pilot_validity.md
```

- `make_jobs pilot_validity`：`state_s0..s2` 的 `out=runs/main/state_s{seed}`，其余 `out=runs/pilot/{name}`；`n64`/`n16` 加 `--episodes 64|16 --tag n64|n16`。
- `exp/analysis/pilot_validity.py`：读取 `eval_samples.npz`，实现 A–D；C 的 10 种划分用固定顺序枚举，bootstrap 种子固定 `default_rng(12345)`；输出每个划分的 `sigma_seed`、`se_boot`、`mde`，以及一条文字结论（"3 种子够 / 需 5 种子 / 需第二份 bench"）写入 `results/pilot_validity.json` 的 `recommendation`。
- E 的实现：`train.py` 增加可选的 `--log-batch-composition`，每 50 步记录 batch 内 `phase==0` 转移占比。
- 新增 pytest：`n64` 数据是 `n256` 的前缀（`--episodes` 取前 N 个）；A/A 枚举数为 10 且无重复。

产出：`results/tables/pilot_validity.md`（附录表 A1：基线排序、阳性对照、MDE）。

## 5. 验收标准（预先登记，结果出来后不得修改）

| 编号 | 条件 | 不通过时的处理 |
| --- | --- | --- |
| V1 | `id` 上 `cascade_f1`：`random_physics` < `apply_edit` + 0.05；`state_s*` − `apply_edit` ≥ 0.15；`state_s*` < `oracle_reseed` | 回到 00 §13 第 4 项；指标或训练有问题，不得进入主实验 |
| V2 | `n256 − n16` 在 `id` 上 CI 排除 0；且 `n256 − n64` 与 `n64 − n16` 至少一个排除 0 | bench 对"更多数据"都不敏感：先检查 bench 是否过易（`copy_last` 关注区格准确率偏高，见 00 §7）或增大 bench；暂停主实验 |
| V3 | A/A 的 10 种划分中，任一划分"CI 排除 0"的比例 ≤ 20%（`id` 的 `cascade_f1`） | 说明配对 bootstrap 低估了训练随机性：主实验改报"种子层级 bootstrap"（先重采样种子再重采样样本），或加种子到 5 |
| V4 | `σ_seed(id, cascade_f1) ≤ 0.02`；`MDE(id) ≤ 0.04` | 见下表 |
| V5 | E：形成转移占比 52.5% ± 3% | `make_pairs` 或采样有 bug，必须修好 |

MDE 决策：

| `MDE(id)` | 主实验配置 |
| --- | --- |
| ≤ 0.04 | 3 种子（按计划） |
| 0.04–0.08 | 5 种子；用新种子再生成第二份 bench（`python run.py --data --seed 1 --out output_b1`，只取其 `bench.npz`，并剔除与 `output/data` 训练成品重复的结构；评测入口加 `--bench` 参数指向它）作确认集 |
| > 0.08 | 暂停；增大 bench 样本量或减小模型/评测方差（例如评测对每个干预多个 oracle 种子取平均）后重做本实验 |

## 6. 预期结果（先验判断，不是测量值）

- 排序：`copy_last`≈0 < `apply_edit`（≈0.05，00 §7）< `random_physics` 低位 < `state`（预期 0.3–0.7）< `oracle_reseed`（≈0.95+）。
- 数据量：`n16` 明显差，`n64` 次之，`n256` 最好；翻倍增益预期为几个到十几个点量级。
- `σ_seed`：预期 0.01–0.03；`MDE(id)` 预期 0.02–0.06，也就是说**实验 03 中"几个百分点"的差异处在可检出边缘**，很可能触发 5 种子 + 第二份 bench。这是本实验最有价值的预警。
- A/A 假阳性率：配对 bootstrap 只含样本噪声，预期略偏高（10%–30%），V3 有一定概率不通过，此时改用种子层级 bootstrap 是正确的做法，不是失败。

## 7. 风险与备选

- 6 个种子只是估计 `σ_seed`，自身不稳（样本 6）：只用来决定种子数，不当作精确值；主实验结束后用实际种子数复核。
- `n16` 训练数据过少导致模型塌缩成 `copy_last`：这仍是合法的阳性对照下端，不算失败；若 `n64` 也塌缩，补 `n128`。
- 本实验只使用 `state`：不检验任何关于 `process` 的内容，这是有意的，避免在设定阈值前接触假设相关结果。
