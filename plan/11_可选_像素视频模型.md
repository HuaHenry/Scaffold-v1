# 11 可选：像素视频模型（稳健性补充）

优先级 P3（**仅当实验 03 的结论已定、且距提交还有 >= 3 天时才做**）｜ 对应：稳健性 ｜ 依赖：实验 03 ｜ 公共约定见 `00`

## 1. 目标

用通用的像素级视频生成架构（不是为网格定制的 GridFormer），在 `state` 与 `process` 两个条件上重复主实验的核心比较，检验"形成缺口"结论是否依赖模型架构。

## 2. 意义

审稿人可能质疑结论只在玩具模型上成立。像素视频模型更接近真实世界模型的训练方式，同时展示 `render -> 模型 -> parse` 的无损往返能支持像素级评测。这是补充，不是主线：主结论为强成功时增强可信度，为负结果时排除"只是模型太小"。

## 3. 实验设计

- 输入输出：`render_layers(fg, bg, cell=4)` -> 帧 `[112,224,3]`；动作条件：把 action map（00 §4）渲染成与帧同分辨率的额外通道（压缩为 8 维嵌入后与帧在通道上拼接）。
- 模型：从零训练的小型视频扩散 Transformer（DiT 风格，约 100–300M 参数）或自回归下一帧扩散；上下文 4 帧（与 FormBench "重复成品 4 帧"一致），预测未来 16 帧，动作逐帧注入。**不使用预训练权重**（否则引入外部先验）。
- 训练数据：`state` 与 `process` 各 1 个种子（时间允许再加 `shuffle`），协议 `video`，同样的帧预算与更新步数 / batch；4 卡 DDP，bf16，记录 GPU 小时。
- 评测：FormBench 四个划分各取 64 个样本，生成未来 16 帧（对应 tick 1–16），`render.parse(frame, cell=4)` 解码；解码后只有合成视图，无法区分前后景，因此评测 `compose(fg,bg)` 的合成视图，指标用 00 §6 的变体 `*_composed`（需在 `metrics.py` 增加）。不在调色板上的像素按最近邻归类并记录占比。

## 4. 实现（本实验独有部分）

```
exp/pixel/data.py        构造 4+16 帧窗口，渲染，编码动作
exp/pixel/model.py       视频 DiT（v-prediction）与采样器
exp/pixel/train_ddp.py   torchrun --nproc_per_node=4
exp/pixel/eval_pixel.py  生成 -> parse -> 指标
```

```bash
torchrun --nproc_per_node=4 -m exp.pixel.train_ddp --condition process --seed 0 --out runs/pixel/process_s0
torchrun --nproc_per_node=4 -m exp.pixel.train_ddp --condition state   --seed 0 --out runs/pixel/state_s0
python -m exp.pixel.eval_pixel --run runs/pixel/process_s0 --splits all --n 64
```

## 5. 验收标准

1. 真值帧 `render -> parse` 往返准确率 100%（pytest）。
2. 训练 loss 收敛；生成的第 1 帧在 `id` 上相对 `copy_last` 有可见改进（否则没学到动作条件）。
3. 与实验 03 采用同一套指标并标注"合成视图"。

## 6. 预期结果（先验判断）

- 像素模型弱于 GridFormer：连锁 F1 更低，生成帧有颜色噪声与格错位。
- 条件间趋势（process 与 state 的相对差别）是主要看点：与实验 03 同向则增强结论，反向则分析原因（容量、噪声、数据量）。
- 1 个种子只能作为方向性证据，论文中不得写成显著性结论。

## 7. 风险与备选

- 成本和复杂度高，是**最先被砍掉的实验**。更便宜的替代：把 GridFormer 的输入换成像素 patch（`render` 后图像 patchify）、输出仍为类别，其余不变，作为输入表示的鲁棒性检验（约 1 小时）。
- 扩散采样随机性使方差大：每个样本生成 4 个取逐格众数。
