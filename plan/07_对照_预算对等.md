# 07 对照：预算对等

优先级 P1 ｜ 对应假设：H1、H2 ｜ 公共约定见 `00`（数据变体接口 §2）

## 1. 目标

排除实验 03 的一个混杂：process 与 shuffle 为了放入形成片段，少看了一半操作片段（4 个 vs state 的 8 个）。本实验分开回答两个问题：

- **Q1（形成的净增益）**：操作片段完全相同时，额外加入形成过程是否有帮助？（`process_96` vs `state_64`）
- **Q2（排除"数据多"）**：`process_96` 的优势是否仅来自总帧数多？（`process_96` vs `state_96`）

## 2. 意义

实验 03 的比较对 process 不利（操作数据减半）。若 process 仍更好，结论更强；若更差，需区分是"形成无用"还是"操作数据被挤掉"。本实验把两种解释分开，防止"不公平"的质疑。

## 3. 实验设计

| 条件名 | 总帧数 | 构成 | 说明 |
| --- | --- | --- | --- |
| `state_64` | 64 | 8 操作片段 | 复用实验 03 |
| `process_64` | 64 | 32 形成 + 4 操作 | 复用实验 03 |
| `process_96` | 96 | 32 形成 + 8 操作 | 操作片段与 `state_64` 的 8 个逐帧相同 |
| `state_96` | 96 | 12 操作 | 总帧数与 `process_96` 相同（按帧数配对，不按内容配对） |
| `partial_96`（可选） | 96 | 12 操作（基础为中间态） | 与 `state_96` 对照 |

- 场景、世界种子、前 8 个干预与主数据一致（由 `(seed,index)` 决定）；`state_96` 的后 4 个干预为 `events[8:12]`，前 8 个与原数据逐位相同（pytest 断言）。
- 协议 `video`，步数与超参同 00 §9（计算量相同、数据量不同），3 个种子。
- 关键比较：Q1 = `process_96 - state_64`；Q2 = `process_96 - state_96`；联合解读 `process_64 vs process_96`（操作片段减半的代价）。

## 4. 实现（本实验独有部分）

```bash
python run.py --gen-train --data-dir output/data_t96 --T 96 --F 32 --n-clips 8 --n-state-clips 12 \
              --conditions state,process,partial
python -m exp.make_jobs budget_parity
python -m exp.run_queue --jobs exp/jobs/budget_parity.json --gpus 0,1,2,3 --eval-after
python -m exp.analysis.budget_table --out results/budget.json --table results/tables/budget.md
```

`make_pairs`（00 §5）从 `train_summary.json["layout"]` 读取片段布局，支持 T=96，不硬编码 64。产出图表：Fig.7 的一格（2×2 对比表）。

## 5. 验收标准

1. `process_96` 与 `state_64` 的前 8 个操作片段逐帧一致（pytest）。
2. 所有设定的步数、batch、超参完全相同。
3. 输出 2×2 对比表（Q1、Q2、操作片段减半的代价、实验 03 的主比较），含配对 bootstrap CI。

## 6. 预期结果（先验判断）

- Q1 是对"形成过程是否提供额外信息"最干净的回答：预期为小的正值（0–5 个百分点连锁 F1），也可能与 0 不可区分。
- `state_96` 比 `state_64` 提升很小（场景模板已被记住）；若 `process_96` > `state_96`，说明增益不是"总帧数多"。
- 若 `process_64` 差于 `state_64` 而 `process_96` 优于 `state_64`：形成过程有用，但被挤掉操作片段的代价抵消，叙事为"形成与操作数据互补"。
- 若 `process_96` 也不优于 `state_64`：支持情景 B / C，转入实验 08。

## 7. 风险与备选

- 时间紧时只做 `process_96` 与 `state_96` 两个新条件。
- 若 `state_64` 与 `state_96` 的差异大于预期，检查 `video` 协议下片段切分是否按 `layout` 执行。
