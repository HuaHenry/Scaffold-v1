# 07 对照：等总预算增长曲线与交叉点

优先级 P1 ｜ 对应假设：H1、H2 ｜ 触发：预实验 02 形成侧 G1/G2 成立、拆除侧出现 S− ｜ 基础数据与统计见 `00`，前置结果见 `01`、`02`。

## 1. 核心问题

在**相同总训练预算**下，`state` 把全部预算用于成品后的操作，`process` 把一半预算用于建造形成、一半用于成品后的操作。**工作假设**：`state` 随预算增加先上升后趋于平台；`process` 早期因为操作练习少而落后，但随着预算增加逐渐追上并超过 `state`。实验要画出两条实际曲线，检验这一假设；不能预先把“饱和”或“反超”写成已经发生的事实。

这不是让 `process` 单独多看操作片段、然后与固定预算的 `state` 比；两者在**每一个档位**都使用相同场景数、总帧数、优化步数、batch、模型、学习率和固定 FormBench。形成阶段占用操作练习量是所研究的**固定预算权衡**，不另做“补课”。

## 2. 主设计：固定视频长度，仅增加场景数

每个 episode 64 帧；`state` 为 8 段操作（64 帧）；`process` 为 32 帧形成 + 4 段操作（32 帧）。数据来自同一份 v3 训练集的前缀，同一档位的两个条件共享场景选择。固定建造与操作各半**按视频帧数**定义。由于形成段的第一帧为初态、操作片段的首帧为重置帧，实际可训练转移分别为每 episode `state:56`、`process:形成31 + 操作28`；训练时对 `process` 的 batch 按形成/操作各抽一半，以使**实际优化更新**也保持 1:1；`state` 的 batch 全部从操作转移抽样。每个模型仍是 6000 步、batch 256，共 1,536,000 次训练转移抽取，不把增加数据量误当增加优化步数。

| 档位（每条件 episode） | 每条件总帧 | `state` 操作帧 | `process` 建造帧 / 操作帧 |
| ---: | ---: | ---: | ---: |
| 16 | 1,024 | 1,024 | 512 / 512 |
| 24 | 1,536 | 1,536 | 768 / 768 |
| 32 | 2,048 | 2,048 | 1,024 / 1,024 |
| 48 | 3,072 | 3,072 | 1,536 / 1,536 |
| 64 | 4,096 | 4,096 | 2,048 / 2,048 |
| 96 | 6,144 | 6,144 | 3,072 / 3,072 |
| 128 | 8,192 | 8,192 | 4,096 / 4,096 |
| 192 | 12,288 | 12,288 | 6,144 / 6,144 |
| 256 | 16,384 | 16,384 | 8,192 / 8,192 |
| 384 | 24,576 | 24,576 | 12,288 / 12,288 |
| 512 | 32,768 | 32,768 | 16,384 / 16,384 |

**默认只用种子 0** 跑完整 11 个档位（22 个训练任务），重点检验曲线形状与交叉。单种子只能描述“这次训练的曲线”，不能证明换随机初始化后也一定交叉；如果要宣称稳健、可复现，再在相同档位补种子或换独立去重 bench。种子扩展是可选后续确认，**不是开始绘图的前置条件**。`process` 使用严格 50% 形成转移的 batch 采样，与预实验 02 的近似 52.5% 不同；不能把 02 的单种子点直接拼到本曲线上。

只增加 episode 数，不改变每 episode 的长度、形成占比或训练步数；横轴是总训练帧/场景数。现有 `data_v3` 只有 256 episode，因此用**同一 v3 生成器和原 seed=0 生成 512 episode 的独立目录**，核对前 256 个 episode 的各条件视频、动作、场景哈希与既有目录完全一致；全部 11 档从这个 512 目录截取前缀。绝不修改旧 `data_v3`。对 512 个训练成品与原 bench、验证集去重；若原 bench 有重叠，生成一份排除全部训练成品的新 bench 并用于**所有档位**。若 512 仍未出现交叉，只能说**所测 1,024–32,768 帧范围内未确认交叉**；后续是否增加到 768/1024 episode 需另行扩展数据、复核所有前缀和同一 bench，不可外推交叉点。

## 3. 对照与测量

- 主读数：FormBench v3 `id` 的 `cascade_f1`，每题先平均两个干预。默认单种子画 `state`/`process` 得分及配对差 `process − state`；同考题 bootstrap 区间只反映题目抽样，不反映训练种子变化，**论文将其称为探索性曲线**。其他三个 OOD 划分作为次级读数，另报 `change_f1`、违反物理的错误率。
- 所有档位使用**同一份**固定 bench，按训练 `final_hash` 检查其与 bench/验证集无成品重叠；报告训练集内部重复但不改变原生成器。核对前 256 个 episode 与原 `data_v3` 完全相同、11 档共享同一份 512 集的前缀。主训练超参沿用 01/02 的 `lr=3e-4, change_weight=8, depth=8, unroll=1`，不看过曲线后再挑超参。
- 最主要问题是差值 `D(B)=process(B)−state(B)` 随预算的变化，而非只看两条均值线是否相交。画四划分预算曲线及 `D(B)` 区间图，表格列出每档种子数、总帧、两者的训练 pair 数、batch 实际形成比例、得分及差值。
- **描述性交叉**：相邻两档 `D` 从负变正，写成“在两个已测预算档之间观察到符号交叉”；不插值报精确帧数。要说“交叉获得统计支持”，相邻低档差值的 95% 区间上界 <0、高档区间下界 >0，且两点的交互差（高档 `D` − 低档 `D`）区间 >0；若仅符号变化但区间含零，明确标作“交叉迹象，未确认”。没有符合条件的档位，就如实报告未确认交叉。多划分与多档同时检验时同时给原始区间和 Holm 修正后的结论，不挑最好看的档位下结论。
- **默认单种子不禁止发表预算曲线**：可以报告趋势和“观察到的交叉”，但不能据此断言换种子也会交叉。若需要稳定性结论，额外增加多个种子后采用同种子与同题目配对的重采样；这是可选的后续复核，不是运行前提。

## 4. 实施与验收

源代码在 `preresearch/07_budget_curve/`；结果在 `experiments/preresearch/07_budget_curve/<运行名>/`。默认生成 `game_code/output/data_v3_curve_512/` 并验证其前缀与旧 `data_v3` 一致；复用 01 的训练、评测和队列，只在 01 的训练入口增加可选 `--balanced-phases`。运行方法见 `preresearch/07_budget_curve/README.md`。

1. 开训前审计：新数据前 256 episode 的数组、动作和场景哈希必须逐项等于旧数据；11 档的两条件都为 64 帧/episode，`process` 各 32 帧形成/操作，pairs 为 `56E/59E`，验证集与全 512 训练成品、选用 bench 与全 512 训练成品不能重叠。
2. 训练：默认种子 0，同档两条件配对，固定 `video`、6000 步和 batch 256；`process` 每个 batch 实测形成比例 50%，`state` 为 0%；11 档共 22 个任务。存档配置、数据哈希、逐题成绩及完成日志。
3. 统计：检查各组是同一 bench 和题序，少一个档或条件就不输出完整曲线；JSON、Markdown、PDF/PNG 保存两条原始曲线、11 档配对差、描述性交叉区间和输入路径。新增数据集若需重新生成 bench，**所有档位都必须用新 bench**，不与 01/02 的原始 benchmark 直接拼接。
4. 结果解释：除了交叉，还须看 `state` 后半段是否接近平台、`process` 是否持续上升；这两项都是可检验假说，不设置“必须饱和/必须反超”的通过门槛。未交叉同样如实报告所测范围内的负结果，不对未测预算外推。

## 5. 限制

每档虽然总帧数与优化抽样数相等，`state` 和 `process` 独特的可训练转移数并不相等（56 vs 59/episode），内容难度也不同；分层采样固定占比，但并不能使两类学习问题同等困难。本曲线识别的是**固定总预算的配置效果**，不是独立估计“形成知识”的纯因果净效应。训练和验证的无动作误改现象沿用 01 发现的单独读数跟踪，不自动视为 07 的通过/失败标准。

## 6. 512 档后续扩展：区分场景数与固定场景的过拟合

2026-11-05 的原始 11 档运行（6000 步、末步模型）至 512 episode 尚未显示数据量饱和：`id` 上 `state` 由 256→512 提升约 0.079，`process` 提升约 0.097；但同一个 512 集训练至末步时，一步验证准确率较较早记录点下降，采样训练准确率已近 100%。前者是**跨数据规模未饱和**，后者提示**固定数据的过拟合或选模不当**，不能混为一谈；一步验证准确率也不等价于自回归 FormBench F1。

新一轮曲线从独立 `data_v3_curve_4096` 中截取共同前缀，保留旧 11 档并加 768、1024、1536、2048、3072、4096（共 17 档；最大每条件 262144 帧、为旧上限八倍）。每档两条件统一上限 12000 步、batch 256、同一学习率计划与验证频率；验证集 `state` 一步 `cascade_acc` 每 500 步选最高 EMA，平分选较早步，**不在任何 bench 划分上选择检查点或超参**。`process` 批内 50:50 不变。增加步数是提高大场景集覆盖度，不把小集末步性能误认为增长空间。

数据生成须核验原 256 所有数组/场景/动作前缀，且新旧结果目录互不覆盖；旧验证集在 4096 训练场景中存在重叠，新一轮需在独立目录从全量训练场景去重生成 32 集验证集，旧验证集绝不覆盖。固定训练、新验证集和统一去重 bench 的文件哈希。作业续跑核验参数及输入、模型和评测身份，拒绝缺失/过期结果。所有新 17 档在新共享 bench 上重新训练和评测，不与旧 512 曲线混画。新一轮默认单种子（34 个任务），结论仍为探索性；若 4096 处继续明显上升，再用相同原则另行扩展更大场景数，而不是宣称提前饱和。
